# 素材消费收敛与需求采集：开发后复核

日期：2026-09-17。审查代码 `e442f9a..7b878c1`，对照上一轮消费方案及目的地关键词建议。未改业务代码、未采集、未调用生成模型、未发布；只读生产文件/SQLite，测试使用临时库及假客户端。

## 结论

部分修复有效，但不接受测试报告“0 个功能缺陷、全量通过”的业务验收结论。可继续小规模生成验证，暂不扩大无人值守矩阵。目的地关键词自动搜索尚未接入；参考优先主题仍被旅行覆盖；并发恢复与预算门仍有可复现缺陷。

本轮运行 8 个相关测试文件：165 passed、7 subtests passed，14.10 秒；未重跑全仓库。另做独立内存/临时库探针，揭示现有测试未覆盖的失效场景。查看最新三个本地成片封面，以及测试报告三条记录的消费合同和规划文件；没有重新读取飞书状态或实测发布。

- 自动发布授权和完整 page_texts 管线在交付文档中已列剩余项，不把它们当作声称已完成的功能。

## 需要修复的关键问题

### 1. [P1] 无主题参考优先仍被强制改成凉爽旅行，账号 brief 未参与终选

位置：`packages/organic_photo_video/services/auto_photo_supply.py:535–539、581–630`。

终选调用仍只传 theme/product/temperature_band。effective_brief 在选材、上传图片之后才构造保存。参考优先没有主题时，仍是 same_item_multiway 且有商品才选一衣多穿，否则凉爽旅行，再推导温度。定位优先缺主题仍直接错误退出。

实记录 `recvvsucYvAnvH`：主素材 `692d497a000000001e00ace9` 为“42 套韩剧女主秋冬氛围感气质穿搭”；topic_statement 虽保存原题，执行 theme 仍为凉爽旅行、温度 15–22°C，规划 theme_key=COOL_WEATHER_TRAVEL。字段保存不等于执行语义生效。

修复：先构造 brief 参与筛选和终选；本篇选题与执行 Recipe 分开；取消自由选题默认温度；缺具体主题但定位存在时允许提炼。增加“配色素材→配色内容”的验收，不能把“参考推导出凉爽旅行”作为通过标准。

### 2. [P1] 采集缺口以分类数量代替真实需求，目的地搜索没有接通

位置：`scripts/export_material_gaps.py:37–55、89–110`，`services/auto_photo_supply.py:488–490、543–545`（均位于 OPV 包）。

库存按原采集 theme 统计任一用途可用数，忽略查询族 purposes、商品、目的地与真实内容结构。实际 no_material 记录又没有这些上下文。国家城市没有进入查询生成；当前旅行查询仅“旅行穿搭/旅行叠穿/出游穿搭多层次”。

只读探针：按实库计算的存量，加入 gap“日本 东京 旅行穿搭，没有可用环境参考”，build_demand 仍返回空列表。旅游冬装任一用途可用 18 篇就足以让旅行族目标 8 看似满足。query_hits 当前四族、11 个命中查询词，没有日本、东京、首尔查询记录，也无旅行族记录。这不能证明从未手工搜过这些词，但本轮自动需求链未实现。

此外，`collect_by_demand.py:136` 用 label“旅行穿脱/层次”入 notes.theme，而配置旅行族 themes 不含它。模拟已有该标签 20 篇，导出仍认定旅行库存为 0，会继续请求补货；这是可触发路径，目前尚无该族实际新增记录，不能说已经反复抓取。

修复：缺口保存简短需求快照；按用途/结构及必要目的地判断候选；查询组合“国家/城市＋内容需求＋相关商品形态”，同时保留通用搭配查询。纯穿搭允许异地参考，借环境才检查目的地。用稳定 family/query_hits 归属，不用展示名当统计主键。

### 3. [P2] 按用途消费仍被旧 prompt 推翻，也缺程序侧校验

位置：`services/material_adapter.py:320–324、430–460`。

初筛允许自拍只借搭配，但终选 prompt 仍写“绝对不要选择镜面自拍/随手拍/poor”，并断言生成必然继承拍摄质感。新旧规则相互矛盾。

另一个内存探针：候选 outfit=true、visual=false，假模型返回 visual_only＋visual_tone 页，select_reference 原样接受。可用用途目前只是模型提示，没有成为实际约束。

修复：删除旧全局摄影排除；对 adoption 与可用用途做最小兼容校验；不能把无效枚举默认 overall；明确仅叙事不发原图、仅搭配可文字化。只有涉及实际采用的维度才限制，不新增综合审美门槛。

### 4. [P1] 建行成功、合同绑定失败后无法自动恢复

位置：`services/auto_photo_supply.py:215–218、250–254、718–720`。

临时库＋假飞书故障注入：外部建行成功，在 attach_record 抛异常。首轮 error；次轮按账号日期统计已经有一行，直接 limit_reached。现有行没有绑定合同，slot 仍 reserved，执行侧又要求合同才能消费。

因此普通重复运行 already_created 不能证明“响应未知/回写失败”恢复正常。来源标记目前仅账号日期，缺 slot/contract 的精确对账。

修复：标记带稳定 contract/slot，先对账恢复未完成合同，再计算新名额；结果未知不能直接重建。租约还应在外部写入前复查所有权，complete_slot 必须校验 owner，避免过期 worker 提交。

### 5. [P1] 调用预算门只检查扫描开始的旧快照，同轮会超限

位置：`services/auto_photo_supply.py:177–178、255–265、284–292`；`services/material_analysis.py:128–133`。

临时库＋假模型：CALL_CAP=1、初始调用 0、daily_limit=2；同轮实际终选 2 次、建 2 行，日志累计 2 次。原因是只取一次预算，未在每个付费调用前更新/预留。

daily_call_usage 只统计 status='ok'，失败不计，和“失败重试也计入”注释冲突；终选失败异常也不会走其后的入账。该 IMAGE_CAP 统计的是素材分析输入图片，不是生图数量，不应称完整生成成本控制。

修复：调用前原子预留、完成后记录结果，失败算尝试；按实际阶段区分分析/终选/生图额度。至少先补同轮 cap=1 和两个 worker 共用预算测试。

### 6. [P2] 待发库存按显示文案、每行一篇计数，真实在制和多篇会漏算

位置：`services/auto_photo_supply.py:196–203、219–222`。

临时客户端探针：一行“素材生成 1/4”加一行“生成中、生成篇数3”，应覆盖 4 篇在制，当前只计 1。只识别完全等于状态名的字符串，且每行固定 +1，不能作为可靠上限。

修复：按既有机器状态和任务/成片唯一 ID 统计；至少兼容实际进度格式和数量，避免重复计数。未绑定账号的手工记录不强行归属。补往日库存、多篇任务、生成中→已发布转换测试。

### 7. [P2] 原搜索入库入口回归损坏

位置：`labs/xhs-material-lab/scripts/search_to_library.py:57–60、77`。

新提取的 import_feeds(conn, feeds, theme, limit) 内仍使用 main 局部变量 args.limit/args.theme。即使内存库和空 feeds 也立即 NameError: name 'args' is not defined。新采集脚本复制了一份实现，所以新入口成功并不能代表旧入口无回归。

修复为函数参数，真正共享入库函数，补旧 CLI 的临时库离线测试。

## 下一步顺序

1. 修复确定性回归和运行可靠性：旧入库脚本、合同绑定恢复、预算、库存。
2. 完成方案核心语义：brief 前置、自由选题不被旅行覆盖、用途规则一致。
3. 接目的地关键词及真实缺口统计；用“东京环境缺口”和“异地仅搭配可用”成对验收，避免增加过度地域限制。

不用再扩大抓取量，也不需要先增加人工审核或换更强模型。现有成果可保留，重点是把保存的配置变成实际执行规则，并覆盖失败恢复场景。
