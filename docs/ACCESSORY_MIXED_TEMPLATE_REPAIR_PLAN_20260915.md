## 二、先确定一个权威来源

继续使用已存在的 `category_execution_extension.mixed_template_contract` 作为执行合同。顶层摘要、creative seed、storyboard、口播输入和提示词都是它的下游投影，不能在各处独立补默认值。

权威分工：

| 信息 | 来源 | 允许的下游操作 |
|---|---|---|
| 商品身份、可见结构、事实/卖点 | 已有商品锚点和批准证据 | 引用、选择，不自行增加部件或功效 |
| 主题、观众问题、叙事节拍 | 已有内容/结构合同 | 选择兼容结构，不由拍摄模板伪造来源 |
| 四镜头顺序、承载、裁切、状态与切镜 | 冻结混合合同 | 按镜头 ID 投影，不重新推断 |
| 环境、光线、台面 | 冻结 environment_recipe 完整快照 | 复用，不按当前配置文件重新选择 |
| 自然文案与细微动作表达 | 模型在以上约束内生成 | 检查是否与合同冲突 |

补齐当前已有字段的实际消费者，必要时增加：

- 稳定的逐镜头 ID。以当前 capture_units 使用的 `capture_unit_id` 为内部标准；旧 `unit_id` 只在读取边界转换一次，后续按 ID 匹配，禁止按序号猜测。
- 单一时间轴来源：根据冻结 `duration_seconds` 累加生成起止时间，统一派生输出 `time_range`；校验时采用毫秒或等价精确表示，不能分别维护两套时长。
- `contract_hash`：覆盖规范版本、商品身份引用、实际镜头约束与完整环境快照。排除运行时间、差异报告、审核备注等可变元数据。
- 内容身份与画面差异签名单独计算，不拿 contract_hash 直接替代语义差异判断。

调整规则语义时升级合同/模板版本，并保留已有版本的读取逻辑。新规则只用于新规划或显式 replan，不静默改写旧冻结合同。

实施步骤：

1. 在新规划入口统一解析 execution scope，将真实任务分支、真实目标时长、是否新规划/续跑、选中的执行模式传入 allocator。不能只根据类目和环境变量启用混合模板。特别核对长视频 DIRECT_PRODUCT 来源借用 15 秒规划请求的路径，必须依据真实父任务作用域排除。

4. 从冻结四镜头清单构建模型需要填充的骨架。模型填写允许变动的视觉描述和动作细节，不能增加/删除 ID 或改变承载和时间轴。
5. 将 `_project_mixed_template_shot_contract` 改成显式映射与校验。重复 ID、缺镜、多镜、未知 ID、非正时长、时间轴重叠/缺口、承载冲突都返回可消费的硬错误。移除按位置静默覆盖的回退。
6. `_make_item` 合同失败时不返回可执行 PLANNED 项。使用现有失败/延期结构持久化 reason code；若现有 schema 无法表达，再作最小扩展。
7. 在执行器调用首个模型之前统一检查：声明混合模式的任务必须有有效冻结合同。规划期失败不能降级到旧模式执行；无混合模式声明且无合同的历史任务继续走原路径。
8. normalize 后再次检查实际脚本与合同；未通过不得进入口播、首帧或生产。允许现有有界修订机制处理模型输出错误，不新增无上限重试，也不为凑数量反复调用。

建议错误码：`MIXED_SCOPE_UNSUPPORTED`、`MIXED_STRUCTURE_INCOMPATIBLE`、`MIXED_CONTRACT_MISSING`、`MIXED_UNIT_ID_MISMATCH`、`MIXED_TIMELINE_MISMATCH`、`MIXED_CARRIER_MISMATCH`。复用已有同义错误码即可。

完成标准：Review 的五镜头样例明确失败，16 秒非法合同不进入模型调用，合法四镜头能完成本地完整投影。

### 阶段 B：按类目、镜头模块、实际结构生成拍摄规则

解决 Review #5、#6。

主要文件：`config/accessory_mixed_templates.json`、`core/accessory_mixed_templates.py`、`core/category_execution/accessory.py`、`core/production_script_renderer.py`。

将当前统一的身体区域规则拆为两层：镜头承载规则 + 商品物理子类型规则。

| 镜头模块 | 画面范围 | 状态/动作边界 |
|---|---|---|
| HANDHELD_PRODUCT | 手与商品，不出现脸或佩戴部位 | 已拿稳，小幅转动；不要求现场摘戴 |
| STATIC_PRODUCT | 商品与台面，商品独立为主体 | 自然静置；不继承耳部/手腕/头部入画要求 |
| WORN_DETAIL | 对应商品的佩戴部位近景 | 已完成佩戴，不生成复杂扣合/穿刺/夹取过程 |
| WORN_RELATION | 同一佩戴部位与袖口、发型等局部关系 | 相较佩戴细节镜头有不同的观察任务 |

佩戴区域：耳饰使用耳部局部且排除眼鼻嘴；腕饰使用手腕/少量前臂；戒指使用手指/手背；发饰使用后脑/头发局部。每镜将允许范围和禁用范围一起输出，避免只写“不露脸”而不定义实际取景。

动作按物理子类型选择：链式手链、刚性手镯；抓夹、发夹、发簪、发圈/头绳等分别处理。动作候选中为具体部件声明必要事实，例如展示吊坠要求 `has_pendant=verified`，展示搭扣要求已验证该结构。

实现三态：VERIFIED / ABSENT / UNKNOWN。UNKNOWN 不当作 ABSENT，也不能触发展示该部件的动作；可降级为已有正面轮廓、颜色、表面纹理观察。没有可用证据时返回候选不足，不新增“搭扣”“耳针背面”等事实。

复用已有锚点/证据结构，新增字段优先作为内部适配，不要求运营重新填写一张产品信息表。

删除蓝图、renderer 中写死耳部的通用句子，改用同一个模块规则投影函数。数量规则区分“商品实际数量”与“当前裁切可见数量”，成对耳饰不要求单耳特写里同时出现两只。

完成标准：各类目三种承载无自相矛盾的裁切；实心手镯不出现链节/吊坠动作；结构未知的商品不被要求展示未知背面。

### 阶段 E：按最终镜头做批次与历史差异判断

解决 Review #3。必须在镜头真实动作和环境投影确定后实现，避免再次给废弃的旧动作计算签名。

主要文件：`core/original_batch_allocator.py`、`core/accessory_mixed_templates.py`、`core/original_batch_executor.py`，及当前批次报告/历史用量存储模块。

先选“本条要让观众看懂什么”，再选择能展示这个主题的模板与证据。例如同一耳饰可以围绕已验证的镂空轮廓或已验证的长度比例设计不同观察；不能自动假定所有产品都有多个足够强的主题。

建议复用当前主题/claim 数据，增加以下比较投影：

- `semantic_signature`：主题命题、观众问题、核心证据所对应的具体意义。不能只使用随机 theme_id 或同义改写后的句子。
- `visual_signature`：按最终镜头记录 module、观察重点、已验证部件、动作、裁切、佩戴关系和首镜任务。
- `surface_signature`：台面、光线配方、颜色风格、BGM等辅助变化，仅用于排期/轮换，不作为新主题的依据。
- `signature_version`：避免新旧签名混用；记录实际比较范围及历史覆盖情况。

首期采用可解释规则，不引入新的向量库或复杂服务：

| 比较结果 | 处理 |
|---|---|
| 最终镜头约束相同，只是序号/旧场景签名不同 | EXACT_DUPLICATE，拒绝重复候选 |
| 同主题、同观察重点，只换环境/BGM/修饰词 | SURFACE_ONLY，不能计入独立脚本数量 |
| 同主题，增加有证据支撑的新观察重点或佩戴关系 | EXECUTION_VARIANT，明确标记变体 |
| 主题问题有实质变化，同时安排了相应可见镜头 | DISTINCT_THEME，可计为新主题候选 |
| 语义是否相同无法可靠判断 | NEEDS_REVIEW，不宣称已经去重通过 |

具体类别名称可以映射现有状态，避免为了这些名称扩张生产状态机。初期不设未经校准的“差异达到 80 分”之类阈值。

候选筛选顺序：生成内容候选 → 编译完整混合合同 → 本批/历史比较 → 接受与预留 → 生成正文 → 用实际正文/最终镜头再核对一次。模型若把两个计划写成相同内容，不能因为计划不同而直接放行。

复用现有历史用量持久化，并补充最终镜头签名。并发预留必须原子化或走现有序列化机制；resume 同一候选应幂等复用自身预留，失败重试不永久占用全新名额。

历史记录如果缺少完整镜头，标注 HISTORY_INCOMPLETE；可以从已有结构化成稿离线提取，但不能从旧 scene_id 伪造最终镜头签名，也不为历史补签名重跑模型。

填写 difference_report，至少包含最近相似候选/脚本、比较依据、实际不同点、候选类型、最终接受/拒绝理由及历史比较覆盖范围。具体字段可沿用现有 nearest_script_id / difference_dimensions / difference_summary / review_status 并最小补充。

数量报告必须区分请求数、独立主题数、执行变体数、重复剔除数、证据不足数和实际可用数；计数不要重复累计同一候选。差异不足时交付较少脚本。此机制用于降低自有内容重复，不能被表述为平台判重保证。

完成标准：Review 的候选 1/4 被识别为重复；只有环境差异不计新内容；新观察点确实进入实际镜头并有可核查报告。

| T16 | 请求 20 条，只有少量足够差异候选 | 按实报告不足，不补随机同义脚本、不无限重试 |
| T17 | 历史重复、并发同候选、resume 同候选 | 复用/排除正确，无重复预留，无重复模型调用 |
| T18 | 长视频借用规划、女装、复刻、其他分支 | 不因全局开关误入配饰 15 秒混合模式 |

在临时数据库与临时数据目录执行；原 200 项相关测试及 allocator/executor、压缩、实际受影响的同步测试全部回归。若现有测试断言的正是错误行为，应按新的明确合同修正测试期望并说明原因。

## 五、旧任务处理与发布验证

先通过只读检查区分旧任务：

- 无混合合同的历史任务：按旧路径运行。
- 有完整且有效冻结合同：按其版本和快照继续，修复投影逻辑，不暗中更换配方/主题。
- 声明混合模式但合同缺失或无效：明确停止并提示需要 replan；不能推测补齐到当前最新模板。
- 已经产出的脚本/首帧/成片：保留原产物，不在本轮修复中批量覆盖。受缺陷影响的任务只读列出，后续按现有任务操作重新规划。

新增灰度仍使用现有开关，并把真实任务范围判断放在新规划入口。关闭开关只停止新混合计划；若需紧急暂停已冻结任务，应复用队列暂停机制，不能通过让它们退回旧模式实现暂停。

代码通过后分两步验收：

1. 离线整链路验收：四类目 × A/B/C，共 12 份完整规划至最终提示词样本；另含手链/手镯和主要发饰物理子类型边界样本。检查最终交接引用确实携带商品身份参考、首帧及冻结约束，不能只查中间 seed。
2. 小批媒体验收：先每类目一款一条，共 4 条成片，通过后再补齐其他模板组合。检查商品身份、手部与耳部合理性、不露脸、三种承载、自然切镜、光线统一、口播事实与自然度。媒体执行沿用现有正式授权/状态入口，不由测试用例触发。

最后做一款商品的 10–20 候选批次检查，输出主题/变体构成与差异报告；允许不足额。成片层面的观感与目标语言自然度作为单独审核结果，不以代码单测通过替代。

## 六、开发模型交付清单

1. 按 A→B→C→D→E 顺序提交可 review 的改动，每阶段写清对应 Review 编号。
2. 每个问题附一个修复前失败、修复后通过的有意义回归，以及实际测试结果。
3. 提供一份合法模板 C 的贯穿样本：冻结合同 → normalized storyboard → 口播输入 → 首帧约束 → 压缩后的最终提示词。
4. 提供一份请求 20 条时的差异报告，包含实际不足额情况及原因。
5. 提供旧任务兼容和长视频隔离验证结果，以及受缺陷影响任务的只读检查方案。
6. 更新相关开发文档与 skill 说明；使用现有验证过的安装同步流程。完成代码修复与离线验证后，明确区分“代码已通过”和“真实样片已通过”。
