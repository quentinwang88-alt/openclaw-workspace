# 攻略型穿搭与配色教程——具体改造执行方案

基线：2026-09-19，HEAD `4a45e42`。
审查依据：`docs/OPV_REVIEW_AND_GUIDE_COLOR_DIRECTION_20260919.md`。
本文为待开发方案，不表示下列新增能力已实现。

## 1. 背景与本轮目标

当前账号配置、自动供稿、外部素材消费、商品/人物参考、旅行与通用生图、排版、中文回写及发布已有可复用链路。纯色背景和浅蓝商品样片已改善，但多篇内容仍趋同为“东京＋裤子还是裙子＋四套展示＋投票”。

本轮要解决两类问题：

1. 账号表精简后的入口回归：指定商品可能不生效；不同账号被统一为灵感表达和奶白基调；空渠道行抢占真实配置。
2. 主题未改变叙事：参考中的教程知识没有完整进入规划；读者只能看到造型名称，教程理由留在长正文或根本没有。

目标是稳定生成“问题明确、图中可见、读者能照做”的攻略与配色内容。保留灵感型生产，不扩大到完整内容中台。

### 明确边界

- 不增加运营必填列、JSON维护、逐篇人工审核或新的后台。
- 账号继续使用现有六列。新需求只增加两个主题选项，任务表沿用现有字段。
- 不改变旧四选一/打卡/一衣多穿主题语义；不修改历史冻结任务。
- 不重构人物包，不切换模型供应商，不增加多轮审美打分或无限重生。
- 首版仅开放TH女装新主题。MX假发、VN围巾、视频和旧拆解流程保持原路由。
- 本轮不顺带修改发布渠道、BGM、账号自动发布授权或全局库存目标。
- 当前其他模型的项链等未提交文件不纳入本轮。

## 2. 运营入口与优先级

新增主题：

| 显示名 | 建议内部标识 | 内容表达 | 默认背景（无任何明确配置时） |
|---|---|---|---|
| 旅行·穿搭攻略 | TRAVEL_STYLING_GUIDE | PRACTICAL_GUIDE | 旅行场景 |
| 配色教程 | COLOR_TUTORIAL | PRACTICAL_GUIDE | 纯色/简洁背景 |

沿用“图文｜TH｜旅行穿搭”“图文｜TH｜四选一穿搭”两个现有入口，不新增生产预设。对新主题，生产预设提供原生图文/市场/生成能力；具体页面结构由新主题的讲解执行配置决定。摘要必须显示“本篇主题＋实际讲解结构”，不能仍显示四选一却输出教程。

接线规则只作用于这两个新主题和TH女装；其他主题维持原预设行为。遇到不兼容的市场、类目或媒体形式，规划前明确提示，不能悄悄改为TH。

主题优先级：本篇明确主题 > 账号明确默认主题 > 自动选题。账号“自动”必须在最前面的解析处归一为空，不只在最后修正。已冻结任务续跑只读原合同。

“参考优先”允许素材决定子问题与方法，但不能擅自把运营明确选择的“配色教程”改成投票。区分明确主题与自动推导，不再把同一个默认值时而当偏好、时而当硬约束。明确的新主题固定讲解类型，素材仍可贡献具体选题。

背景独立于主题：本篇视觉预设 > 已有账号有效预设 > 新主题默认。东京攻略也可用纯色背景；普通配色教程不强制城市。

操作例：

- 账号长期做攻略：默认主题选“旅行·穿搭攻略”，目的地范围选东京/首尔，后续预算供稿自动产生具体问题。
- 本篇做配色：任务主题选“配色教程”，可填商品编码，在内容要求写“讲清浅蓝外套与灰色、奶白、棕色如何搭配”。
- 内容要求为空：从账号定位、商品及选中参考中提炼问题；不要求运营逐篇想标题。

## 3. Phase A：先修账号与有效需求

### A1. 填码即指定

模块：`skills/short-video-auto-publisher/app/scheduler.py`、`run_pipeline.py`；OPV `services/publish_account_profile.py`、`auto_photo_supply.py`。

- 新简化账号入口：指定商品编码非空 → product_mode=specified；空 → none。
- 兼容旧调用显式mode；对矛盾输入明确归一或报原因，不静默忽略编码。
- 统一建字段、读取别名和旧“默认产品编码”迁移，保留旧数据。
- 任务本篇显式商品优先于账号默认；续跑以冻结商品为准。
- 从实际账号行字段测试到供稿商品解析，不能继续只测手工传旧mode的函数。

### A2. 默认值只补缺省，保留账号差异

- 撤销所有账号无条件写STYLE_INSPIRATION/奶白基调的行为。
- 空内容配置行返回空profile，不抢占另一渠道行的有效配置。
- 复用既有账号seed/存储配置/视觉预设继承规则。两个渠道都有明确内容值时，采用既有稳定来源规则并报告冲突；不随机合并两个不同主题。
- 新主题自动映射PRACTICAL_GUIDE；旧主题保留既有表达兼容。
- 定位文字进入规划，明确风格继续继承；不新增“风格故事/标签库”，不每次供稿再调模型解析账号。
- 保留现有账号领取范围与发布映射，避免借内容升级改变路由。

### A3. 一份有效需求贯通

- 在选材前归一“自动”、商品模式、明确主题、地点要求、视觉预设及温度来源。
- 定位优先旅行任务先选城市，再筛选/终选；既有一次终选用于选子问题和素材，不增加调用。
- 无温度需求保持明确为空；执行profile不得再补15_22c。温度攻略必须有明确温度条件，不能把目的地或月份直接当实测天气。
- 具体地点缺失时在供稿前处理，沿用已实现的合同地点补齐。
- 合并新旧两段对账入口，避免同日补绑再次抛异常终止整批；保持未知提交账号级暂停。

验收：指定编码实际进入product_context；空渠道行不覆盖配置；攻略账号获得指南表达；无温度任务最终prompt与文案均无默认温度；补绑故障不影响第二账号。

## 4. Phase B：增加共用讲解合同，先规划页职责

### B1. 架构落点

复用：`effective_brief → external_supply_contract → style_profile/content_plan → frozen request → photo_package`。

新增一个共享讲解执行配置，两个新主题引用它，不新建两套生成引擎。配置可放在现有 `config/photo_planning_policies/`，由现有recipe-policy解析器在新主题下显式引用；旧主题仍走原policy。不要在多个阶段各写一次主题字符串判断。

执行结构首版统一为：4个源角色look_a/b/c/d、4张成片；首张用look_a，不从后面选封面，不增加第五张重复封面。保持现有生图数量上限，降低改造范围。

对新主题增加一份程序维护的 `narrative_plan`（或等价字段）：

| 字段 | 用途 |
|---|---|
| version、kind | 版本；travel_guide或color_tutorial |
| question_zh | 本篇具体回答什么问题 |
| takeaways | 2–3条读者能照做的方法 |
| pages | 四页有序计划：page_index、source_role、page_role、要点、画面依据、发布语言文字、可选色卡 |
| reference_basis | 相关参考note/页码和借鉴的方法，便于追溯 |

复用已有styling_intent、palette_hex、商品事实与look描述；不要把同一信息复制成多份可独立修改的结构。narrative_plan引用对应source_role，具体衣服仍由look合同持有。

源角色A/B/C/D只作为内部寻址，教程画面不强制印字母，不使用“请选择ABCD”的默认CTA。

### B2. 进入既有规划调用

模块：`services/photo_reference_vision.py`、`photo_content_planner.py`、`feishu_workflow.py`。

- 在现有规划调用内同时产出页职责、穿搭、画面与文案，不另加一个“教程策划模型”。
- 提示词按新讲解配置选择唯一规则块，不能同时附带“每页只能造型名称”和“每页需要解释”。
- 先确定问题和takeaways，再让每套造型承担相应证据；允许同一单品、相近造型、局部差异。
- 新教程不使用pants_or_skirt默认选择轴，也不强制四套在轮廓/颜色/场景全部变化。
- 背景、人物、商品、参考用途仍复用现有合同，不能被narrative_plan覆盖。
- 两个入口共享相同输出校验。旅行入口不先造5页再去重，通用入口不自动补四宫格；新合同直接产出4页。
- 下游页数、中文回写、发布包检查读取新合同的4页定义；旧任务原规则不变。

### B3. 文案统一来源

- 最终title/caption/page_text/CTA由同一问题与最终计划产生，中文回写来自最终发布文字。
- 中文规划问题不能漏进泰文；语言校验按真实publish_locale。
- 现有CJK兜底不能把教程静默换成通用四选一话术。优先使用既有一次文案修正能力，仅修改文字；仍失败则保留图片和失败原因，不为了文案重生图片。
- 若使用本地兜底，只允许同主题、同页职责、同语言的安全短文案；没有可靠兜底就不宣称教程完成。
- 数字承诺来自takeaways及页面实际内容，不沿用参考的8套/18图数量。

## 5. 两个主题的首版页面设计

### 5.1 旅行·穿搭攻略

首版优先做“长时间步行如何搭配”“室内外穿脱”“少带衣服如何组合”三个问题方向。方向由已有账号定位/内容要求/参考选择，运营不增加子分类字段。

示例：东京一天走很多路，怎么穿方便又好拍？

| 页 | 职责 | 图片与文字 |
|---|---|---|
| 1 / look_a | 问题＋整体答案预览 | 单张完整穿搭；标题＋一句总原则 |
| 2 / look_b | 第一条建议 | 造型突出裤脚与鞋的衔接；标题“裤脚与鞋”，一句可执行建议 |
| 3 / look_c | 第二条建议 | 外层易穿脱、内搭可独立穿；画面确实展示相关部位 |
| 4 / look_d | 第三条建议＋收束 | 造型体现配件/组合复用；短理由＋一句总结或收藏提示 |

不要求每页换地标，场景服务本篇问题。相同人物、色调和版式允许稳定，变化集中在讲解内容。

首版继续四张可生成的造型图，不要求多动作连续叙事或商品拆件。必要细节从真实生成图裁切、标注；图中没有的内层/背面不能靠文字声称已经展示，需在规划时安排可见构图。暂不做精细抠图与服装识别系统。

### 5.2 配色教程

示例：浅蓝外套怎么配？三种容易应用的配色方法。

| 页 | 职责 | 图片与文字 |
|---|---|---|
| 1 / look_a | 提问与完整效果 | 一套吸引人的浅蓝搭配＋说明后续讲三种方法 |
| 2 / look_b | 方法一：浅色衔接 | 浅蓝＋奶白；标明颜色对应单品和轻盈感来源 |
| 3 / look_c | 方法二：明暗对比 | 浅蓝＋深灰；说明深色的位置和作用 |
| 4 / look_d | 方法三：局部呼应 | 浅蓝＋棕鞋/包；说明点缀呼应，附简短总结 |

look_a不是从b/c/d挑出来重复；四套都可围绕同一商品，方法示例可相近，不强制换不同大衣。无指定商品时允许自由搭配，但每页仍围绕同一个配色问题。

色块由程序画，关联衣服/鞋包的角色；使用规划色卡与已有图像QA中的可见颜色判断，明显不符时修色卡/说明，不把模特重生作为首选。首版不要求精确色值或60/30/10比例。

教程按一条明确方法展开，不把四种颜色名字当四条知识，不用“好看/高级/显贵”替代解释。

## 6. Phase C：素材如何被消费

模块：`services/material_analysis.py`、`material_adapter.py`、`auto_photo_supply.py`、`external_supply_contract.py`；lab查询配置。

- 保留既有逐页摘要与用途可用性。在现有分析/终选响应中补充可复用的搭配方法、证据页、说明顺序，随选中素材合同冻结。
- 输入规划的是选中素材的相关页摘要，不把全文、全库图片反复发送。
- 文字丰富的攻略可标为“仅叙事可用”；不可生图参考与不可叙事参考分开。忽略来源水印/标题复制，按实际商品改写。
- 指定商品时，参考主商品颜色/材质不能进入执行要求；配套关系继续用。无法可靠拆开的冲突原文留在来源记录，不整段注入。
- 同一张图允许穿搭＋色调等多用途；用途白名单由合同控制，模型分析不扩大到环境。
- 教程没有合适参考时，可用现有规划能力基于商品和问题独立规划并记录“独立规划”；不为了通过素材门强制选择不相关参考。人物/商品资料缺失等真实硬条件仍遵守现有规则。
- 不增加全库分析。按需求筛相关note_ids，每轮继续共用最多5篇补析预算，当前指纹有缓存就复用。

采集词使用自然问题：日本旅行穿搭攻略、城市步行穿搭、短外套旅行叠穿、浅蓝外套配色、上浅下深、鞋包颜色呼应。配色教程不要求东京/首尔素材。

复用同一轻量匹配判断消费与缺口满足：仅借搭配允许异地；环境需要相容。不能用“所有目的地需求永久保留”替代满足判断，也不能用族总量清掉具体需求。搜索尝试冷却和来源关联沿用现有结构，本轮不扩大抓取量。

## 7. Phase D：版式修复与讲解呈现

模块：`services/photo_package.py`、`photo_structured_layout.py`、`visual_preset.py`、最终layout_snapshot构造点。

### D1. 修既有四宫格

- 最终模板和grid拼合使用同一份区域几何。图片区80%时，标题必须进入剩余文字区，不再沿用structured默认top。
- 格子缩短后不能仍不加判断地中心裁切。优先等比完整容纳人物；有限留边可以接受，不为了填满格子裁掉头脚。
- 该修复作用于明确的grid页面；旅行单图和其他市场既有排版不顺带切换。

### D2. 教程只加两种呈现

1. 攻略：主图＋简短讲解区，必要时复用局部细节。
2. 配色：主图＋色块/单品名＋一句配色理由。

复用现有泰文字体、字号层级和换行。教程页面可预留约四分之一给说明，比例由实际长度有限调整；这是布局默认，不是运营字段或全模板规则。别在复杂街景上铺长文。

讲解页只保留小标题、一句方法、必要色块/标注；较长补充进caption。超长优先缩短表达，不无限缩字号。色块/文字程序渲染，生图输出无字底图。

中文回写包含发布标题、正文、每页全部显示文字、色卡名称及CTA，顺序与成片一致。内容摘要回显主题、讲解类型、问题、商品、目的地及视觉预设，运营无需看内部合同。

## 9. 验收矩阵与开发顺序

按A→B→C→D推进，D1可独立修复。先写能复现断点的集成测试；模型、飞书、搜索mock，但实际调用者与消费者都走真实代码。

必须覆盖：

1. 账号指定编码→指定模式→冻结商品→生图请求，非空码不丢。
2. 空渠道行＋有配置渠道行，定位与自动化策略不被空默认覆盖。
3. 任务主题覆盖账号默认；冻结后改账号配置，续跑不变。
4. 两个教程主题进入PRACTICAL_GUIDE和讲解policy；旧四选一保持原copy/页数/QA语义。
5. 新教程真实规划prompt不含互相冲突的“只写造型名/强制投票”要求。
6. 無温度旅行指南最终合同和copy无15–22°C；显式温度按来源保留。
7. 参考的讲解方法/证据页进入实际规划输入；外部商品描述不覆盖指定商品。
