## 1. Review #9 —— 逐镜观察要求被提升成"每段"

### 1.1 修复前的真实故障

`production_script_renderer` 每个镜头段都会输出自己的观察要求：

```
【拍摄片段01｜0.0-4.0s｜HOOK】
画面事件：…
商品必须可见：耳饰整体轮廓

【拍摄片段02｜4.0-7.0s｜PROOF】
画面事件：…
商品必须可见：背部耳针连接处
```

这**不是重复**——「整体轮廓」和「背部连接」是两个不同的观察任务，正是任务书要求按镜头保留的东西。
但压缩的 L2 只看标签同名，就把第一条改写成「每段商品必须可见：耳饰整体轮廓」，其余三条**整行删除**。

后果是视频模型收到的合同变成：

| | 原意 | 压缩后 |
|---|---|---|
| 片段 01 | 看整体轮廓 | 看整体轮廓 |
| 片段 02 | 看背部耳针连接处 | **看整体轮廓**（错） |
| 片段 03 | 看耳垂贴合关系 | **看整体轮廓**（错） |
| 片段 04 | 看耳廓与领口关系 | **看整体轮廓**（错） |

即：一个错误的全局断言 + 三个被静默删除的约束。

### 1.2 修复内容

**提升现在需要全部镜头一致**（`_normalize_constraint` 去掉标点空白后比较）：

```python
anchor_positions = [...]                      # 所有「商品必须可见」行
anchor_values = {normalize(value) for ...}
lift_anchors = len(anchor_values) == 1        # 只有一种值时才是全片要求
```

- **完全一致** → 仍合并为一条 `每段商品必须可见`（保留原有去重能力，T13 的"相同要求可合理去重"）。
- **存在差异** → 每一镜保留自己那一行，**不做任何改名**。

修复过程中踩到一个自己引入的 bug 并被探针抓住：第一版把**所有**锚点行都改名成「每段商品必须可见」——
比修复前更糟（等于把每一镜的要求都断言到其它三镜）。探针的 `不得把第一镜的观察要求提升为『每段』` 一条直接命中。

### 1.3 量化代价

同一份 4051 字符复现样本：

| 规则集 | 压缩后 | 去掉 |
|---|---|---|
| 旧规则集 | 3436 | 615 字符 |
| 新规则集 | **3619** | **432 字符** |

保护代价 **183 字符（约 4.5% 压缩力）**，换回 3 条被静默删除的镜头约束与 1 条错误断言。
这是有意的取舍：任务书要求"优先删除解释性长句与重复修饰"，而不是删约束。

## 2. 保护项（要求 3）

任务书要求保护：商品身份、逐镜锚点、承载、裁切、时间轴、动作边界、切镜关系。
核对代码后发现**文档声称已保护但实际没有**的项目：

| 保护项 | 标签 | 修复前 | 修复后 |
|---|---|---|---|
| 动作边界 | `动作类型` / `开始状态` / `核心动作` / `结束状态` | ❌ 不在保护名单，**会被同值行挤掉** | ✅ 进 `SHOT_CORE_LABELS` |
| 承载 | `出镜方式` / `承载方式` | ❌ 在 `L4_ELIGIBLE_LABELS`，可被从句级去重削掉 | ✅ 移出 + 进保护 |
| 裁切 | `商品观察尺度` | ❌ 同上 | ✅ 移出 + 进保护 |
| 切镜关系 | `连续性` / `公共场景拍摄关系` / `拍摄关系` | ❌ 同上 | ✅ 移出 |
| 时间轴 | `【拍摄片段01｜0.0-4.0s｜HOOK】` | ✅ 事实未丢，但无断言 | ✅ 新增 `SHOT_HEADER_RE` 显式校验 |

`SHOT_HEADER_RE = ^【[^】]*?\d{1,2}\s*｜[^】]*】$` —— 数字必须在 `｜` **之前**。
这条约束让 `【拍摄方式｜UGC_NATIVE_V2_MULTICLIP】`（数字在 `｜` 之后）不会被误判成镜头标题，
而 `【拍摄片段01｜0.0-4.0s｜HOOK】` / `【连续内容段01｜…】` / `【片段01｜…】` 都能识别。

## 3. 每镜归属审计（要求 5）

任务书原文：「压缩后核对每镜保护项归属。不要只验证关键字还出现在全文中，否则第一镜约束挪到第四镜也会误判通过。」

新增 `audit_shot_protection(before, after, *, lifted=())`：

- 先把文本按镜头标题切片；
- 对每镜的每个受保护标签，**压缩前有、压缩后必须仍在这一镜**；
- 若值出现在**别的镜头**里，报「被挪到了片段 NN」；完全找不到才报「丢失」。

用例 `test_a_migrated_constraint_would_pass_a_whole_text_search` 专门证明这个审计不是多余的：
同一个坏样本，全文关键字搜索通过，归属审计失败。

`audit_protected_text(before, after)` 另做两层校验：镜头标题不得被丢弃或改名、两个受保护段落必须逐字存活。

## 4. 超限状态（要求 4）

任务书要求「超限且仍有必须保留的约束时，返回明确的超限状态，走现有可处理路径」。

**先确认了"现有可处理路径"到底是什么**：在整个工作区检索 `video_prompt` 的消费者，`render_video_generation_prompt` 的产物只被持久化，
下游没有超长重试/裁剪处理器。因此唯一诚实的做法是：**不截断，把状态报出来**。

新增 `compact_video_prompt_report(prompt, limit) -> CompactionReport`：

```python
@dataclass(frozen=True)
class CompactionReport:
    text: str                 # 下游真正用的文本
    original_chars: int
    limit: int
    applied: bool
    over_limit: bool          # 去完冗余仍超预算 —— 已尽力，不截断
    protected_dropped: tuple  # 恒应为空
    shot_migrations: tuple    # 恒应为空
    ok: bool                  # 上面两项都空
```

`compact_video_prompt(prompt, limit=None)` **签名与返回类型不变**，内部委托给报告版并取 `.text`。
渲染器同理：`render_video_generation_prompt` 返回字符串（逐字不变），新增同源入口 `render_video_generation_prompt_report`。

这让"这块的改动对公共路径的影响"可被独立验证：**所有既有调用方拿到的字符串一个字节都没变。**

## 6. 本阶段留下的关键事实

1. **`compact_video_prompt` 的返回值语义没变**，超限信息只在 `CompactionReport` 里。任何"靠长度判断压缩是否成功"的新代码都应改用报告版。
2. **`_long_prompt()` 这个测试 fixture 的压缩下限是 1452 字符**。写 `limit=600` 的断言时不要假设能压到 600——那个数字本来就不可达，超限是正确行为。
3. **`SHOT_HEADER_RE` 要求数字在 `｜` 之前**。新增镜头标题格式时（例如 `【第01段｜…】`）要确认仍能匹配，否则该镜头的约束会失去归属保护。
4. **`商品必须可见` 只在全部镜头一致时才允许改名为 `每段商品必须可见`**；改名（而非删除）也算一次合法提升，会通过 `lifted=` 传给审计以免误报。
5. **`本段手机构图` 故意不在审计名单里**：L2b 会在它只是复述本镜自己的画面事件时删掉它 —— 同镜内删除，没有东西被挪走。
6. **下游没有超长提示词处理器**，`video_prompt` 只被持久化。所以"超限走现有可处理路径"= 不截断 + 报状态。
