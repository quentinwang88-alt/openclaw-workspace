## 2. 优先修复的关键断点

### P1：目的地选出来了，但正式生成入口仍可能直接失败

位置：`packages/organic_photo_video/services/auto_photo_supply.py:817,873,1044`；`services/feishu_workflow.py:1732,1810`；`build_travel_topic` 在同文件 `:363`。

现状：定位优先账号在终选以后才轮换目的地；终选 prompt 未包含最终选中的东京。供稿器写“旅行国家”，明确停写“旅行地点（可选）”。执行器仍只从行字段读取地点；具体旅行主题缺地点便报错，没有从冻结外部合同补齐。

隔离实证：账号配置“旅行·打卡穿搭 + 东京”，自动供稿创建 1 行；实际终选 prompt 不含东京，行字段只有日本，调用现有主题构造得到“请填写旅行地点”。正式记录 `recvvwwsjVgrTM` 的运行记录也明确记载人工补东京后续跑成功。因此“目的地范围为空才失败”的解释不准确：范围非空、合同已选东京，仍会因消费入口断开失败。

最小修复：定位优先先解析目的地，再筛选/终选；执行入口按本篇显式字段 > 冻结合同读取城市，保持程序内部文案 token 与城市显示文字分离。不要为绕过 token 问题删除业务输入。重试沿用冻结目的地。

验收：从账号配置开始，创建的原始行无需人工补字段即可通过具体旅行主题构造；实际终选 prompt、合同、规划 place、封面城市一致。
