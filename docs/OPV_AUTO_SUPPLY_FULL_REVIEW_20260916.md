# 自动图文供稿：方案、实现与参考效果复核

审查日期：2026-09-16。代码基线：`e442f9a`。本轮仅审查、运行隔离测试并写本文；未修改业务代码、账户配置、定时任务或发布任何内容。

## 结论

本轮外部参考的执行路径修复有效，已能选材、自动建任务、重新生图、排版。原“账号策略驱动的无人值守生产与发布”大方案仍只完成部分，不能按完整交付验收。

小红书参考确实影响了配色、单品和叠穿，但其内容主张没有被充分保留；无主题账号仍被强制导向凉爽旅行，部分参考装饰又被直接继承。应先完善消费，再按生产缺口补素材。当前不需要推倒已有 OPV，也不需要扩大人工审核。

## 3. 关键发现与最小修复方向

### A. 参考内容被旧主题路由覆盖，是目前效果问题的首要原因

证据：`packages/organic_photo_video/services/auto_photo_supply.py:414–431`。无默认主题时，只有 same_item_multiway 且带商品被定为一衣多穿，其余都是凉爽旅行。`material_adapter.py:350–379` 的终选没有账号受众、视觉风格、目的地输入。

实际例子：素材 `68f31bf70000000004017bd1` 原题为秋冬日系内搭灵感，最新参考优先任务最终变成通用凉爽城市旅行四选一；两条定位测试最终标题也相同。参考的“为何这么搭”没有成为内页主线。

最小修改：沿用现有字段，分别保存本篇内容主张与内部执行 Recipe。参考优先从素材提炼主张，账号定位和商品提供边界；内部用既有四页生产能力不等于必须讲旅行。无明确温度不自动补 15–22°C。定位优先未设具体主题时，允许在已配置定位内推导。

选材传入一份由现有账号字段拼出的短 brief，不新建账号标签体系。指定商品时商品事实优先，自由搭配才可调整单品。

### B. 参考有效，但信息提取过薄、采用边界不清

实际对照：参考里的米白开衫＋藏蓝衬衫＋棕长裙、绿棕配色，以及另一篇牛仔叠马甲等组合进入了成片。这说明参考有价值。

同一篇参考里的 Q 版人物也进入了 `recvvojd659NmU`：前三页有、第四页没有，大小和画法不统一。这不是单纯生图随机出错，供稿内容要求已把“同款 Q 版人物”作为参考主题转交下游。当前把内容结构、搭配价值、装饰混成一项。

最小修改：在现有一次 Doubao 分析里加入原始标题/正文截断、每页一句“可见搭配与差别”、最小 outfit_set 分组；终选才能知道 detail 页具体是什么，而非只收到页码和角色。冻结选中后的主张、每页要回答的问题、需借鉴的搭配关系。不要增加一轮逐张视觉审查。

采用边界：搭配参考默认借单品关系，视觉参考才借配色/背景/构图；源图贴纸等只有与账号视觉方向相容且实际选中时才传入生成，不设逐项黑名单。仅借叙事应能不传原图生产。outfit_only 没有细节页时，可走文字化搭配，不应把“只有全身图”等同于完全不可用，也不要偷偷退回 overall。

分析加入正文后，缓存键应包含相应文本摘要/版本；`analyze_pending` 应比较当前指纹，不能只因 note_id 分析过而永远跳过更新。按需更新，不全库强制重跑。

### C. 字体可读性有实际程序错误，不需要再重做一套排版系统

`services/photo_structured_layout.py:289–299` 在同一 RGBA 层反复画大矩形。封面最后一步 alpha=0 覆盖前面区域；内页的着色主要缩在区域上缘，文字位置得不到有效衬底。

本轮局部探针：纯白 1080×1920 画布、top=100、bottom=220、scrim_alpha=118、fade=100；封面与内页在 y=100/130/170/210 的像素均仍为 255。与样片白墙/天空上米白字看不清一致。

另一个原因在 `parse_page_spec():64`：封面两行固定“第一行小标、第二行大标题”。当前 copy 第一行是实际问题、第二行是 A B C D，因此结构化排版把投票字母做成视觉主体。

最小修改：修正逐行 alpha 遮罩；主问题作为 headline，地点/温度为小标，投票提示为较小 CTA。复用当前结构化渲染器与文案同源机制。只补明暗背景可读性和标题层级的回归，优先复用原图重新排版验收，避免重新生图花费。

### D. 无人值守前必须修复供稿名额和合同恢复

`material_analysis.py:206–220` 第二个 worker 可以拿到 reserved；`auto_photo_supply.py:258–263` 仅 created 跳过，所以 reserved 仍继续执行。临时 SQLite 双连接验证得到 newly_reserved / reserved。

`external_supply_contract.py:125–164` 返回旧 intent，调用方 `auto_photo_supply.py:468–511` 只取 ID，建行仍使用这次重新选的图片和内容。存在“冻结 A、执行 B”路径。

最小修改：单账号/名额的原子执行租约，失败后可恢复；重试从冻结 intent 恢复完整输入；建行标记携带 contract/slot 供准确对账。先做并发、建行成功回写失败、选材后中断三种隔离测试。

### E. 按库存生产与自动发布尚未闭环，要明确剩余交付范围

`auto_photo_supply.py:181–227` 只算当日自动建行。正式入口 `scripts/run_auto_photo_supply.py:107–114` 未传分析器，0 候选在供稿服务 `:343–354` 提前退出。`release_gate.py:129–145` 仍为人工审核。

最小修改：先接现有任务/发布状态统计可用及在制库存，避免积压仍新增；选材无候选时调度有限补分析，再给出机器可读缺口；自动发布采用账号显式策略授权快照接现有发布流程，不能伪造 human，也不应让用户逐篇点确认。额度复用现有调用台账扩展，终选 usage 也纳入。

这是自动模式的补完，不建议修改历史人工任务的放行语义。

## 4. 搜集方式需要优化，但先解决消费错配

本地统计：119 篇素材、969 张图片；104 fetched、8 partial、7 failed。v2 已分析 45 篇/421 图，31 篇可消费，其中 independent_collection 25、mixed 3、same_item_multiway 3、layered 0。

可用库存明显偏向独立造型合集，不足以支撑各账号的一衣多穿、叠穿讲解等需求。结构标签也应以逐页变化核实：同一套衣服换角度，不等于一衣多穿。

现有入库分类以旅游冬装、旅游穿搭、显高、秋冬、轻上装等宽词为主；新增旅游穿搭、轻上装基本未进入 v2 分析缓存。继续宽泛加量可能只扩大未分析库存。

建议建立少量共享查询族，由账号生产缺口汇总驱动，运营不用每个账号维护搜索词：

| 生产需求 | 搜索意图示例 | 消费重点 |
|---|---|---|
| 一衣多穿 | 同一件短外套 不同下装；围巾 多种搭配 | 固定主单品、其余搭配真的变化 |
| 旅行适配 | 东京 秋天 分层穿搭；旅行外套 方便穿脱 | 旅行需求和穿脱逻辑；不把搜索词当温度事实 |
| 自由选题 | 灰色穿搭 层次；咖色 配色；短外套 鞋子搭配 | 保留具体内容价值，不强改旅行 |
| 指定商品 | 规范品类＋可见版型/颜色＋搭配需求 | 不用内部商品编码搜索；以真实商品适配 |

旅行穿搭参考不必拍在目标国家。只有借环境时，目的地匹配才需要参与筛选；仅借穿搭可以跨地点。

把当前 gap 结果汇总成采集侧下批输入，消费侧不调用浏览器。优先分析活跃账号/商品需要的未分析素材。`search_to_library.py:69` 同 note 冲突目前丢失后续搜索来源，可保留 query 多值来源以判断哪些词真正提供可用素材，不需建立复杂推荐系统。

放松低价值摄影硬拒：`material_analysis.py:322–326` 和 `material_adapter.py:238–243` 仍把自拍/摄影差整篇拒绝。搭配清楚的图可供文字化借鉴；摄影质量差主要限制视觉采用。最终作品继续使用已有硬灾难 QA，不新增逐篇人工审核。

Token 台账：v2 45 篇记录合计输入 585,676、输出 45,564，平均每篇约 13,015 输入和 1,013 输出。不是价格，不含完整终选/失败/生成成本。Doubao 适合继续承担这层工作，优先优化分析对象和一次分析的信息利用，不建议先换大模型或再加多轮 QA。

## 5. 下一轮建议及验收

先做三个工作包：

1. **消费语义与成片表达**：自由主题与执行 Recipe 分开；有效账号 brief 进选材；逐页参考摘要和采用边界；修复渐变与标题层级。验证选题未被改写、搭配理由进入内页、浅色背景可读。不新增大量预设。
2. **自动运行可靠性**：租约、冻结合同恢复、库存上限、空候选补分析；之后接真实自动发布授权。先隔离故障测试，再限量开一个授权账号，不能把“生成完成”当自动发布闭环完成。
3. **按缺口补素材**：使用少量查询族、按需分析、保留搜索来源；用每个需求得到多少有效候选及是否真的被消费衡量效果，不追求原始抓取量。

最小内容验收集可以是 4 条：定位优先＋商品一衣多穿；定位优先＋自由旅行；参考优先＋无主题配色题；参考优先＋指定商品。故意选不同源笔记，使用真实终选，不固定返回素材。另用隔离测试覆盖零图 narrative、只有全身图的 outfit_only，避免付费后才发现不可执行。

现有 4 页图像规格、泰国人物包、商品保真、原生图文输出和既有发布链路继续复用；不扩展复杂推荐、账号晋级或新后台。本轮 review 不等于授权执行下一轮修改或发布。
