# 图文自动供稿下一轮优化执行方案

日期：2026-09-18。核对基线：`1b8f3ef`。

依据：`OPV_DESTINATION_CLOSURE_REVIEW_20260918.md`。本方案是既有目的地与素材消费方案的断点修复，不取代现有生产体系。开工时先查看 git diff；如其他模型已改同一处，核验后合并，勿重复覆盖。

## 一、背景、目标与范围

当前已有账号内容配置、每日自动供稿、参考素材采集/分析/终选、外部供稿合同、旅行及通用生成、视觉预设、商品与人物参考、排版、中文回写和发布链路。上一轮已修复同 slot 未知响应重建、部分跨日恢复、未知库存保护和图片分析额度。

本轮审查发现的主问题：同一业务需求在不同阶段被重新猜测，或只写入合同但未传给消费者。由此出现合同有东京而生成报缺地点、纯色任务变街景、指定浅蓝商品仍受米白参考干扰、旅行素材总量掩盖具体目的地缺口等问题。

本轮目标：让账号配置/本篇要求一次解析后，可靠地贯通选材、规划、生图、排版与回写；补齐自动运行异常保护。

边界：

- 不新增运营必填字段、人工逐篇审核、账号等级、推荐系统或数据看板。
- 继续使用现有账号管理表、图文任务表、素材库、合同库、生成和发布入口。
- 不改变已稳定的 TH 手动生产语义，不把 TH 通用路径套给 MX 假发或围巾。
- 不调整本轮之外的发布渠道、BGM、人物包、视频生产；样片验收不等于发布授权。
- 不因修复而全库重分析、批量重生或自动重置历史冻结任务。
- 原生旅行首图沿用第一套穿搭，不增加四合一旅行封面。

## 二、统一数据流与优先级

沿用 effective_brief、external_supply_contract、content_plan、layout_snapshot，不新增平行业务对象。

```text
账号配置 + 本篇显式要求
        ↓ 首次解析
有效需求：主题/目的地/商品/视觉预设/参考用途/温度来源
        ↓
候选筛选 → 一次现有终选 → 冻结合同
        ↓
生成入口读取合同 → 规划 → 生图 → 最终模板排版 → 中文回写

候选不足 → 同一需求记录 → 素材采集 → 有限分析 → 下轮消费
```

优先级分首次运行和续跑，避免“显式字段优先”破坏冻结：

| 情况 | 处理 |
|---|---|
| 首次手动任务 | 本篇明确值优先；缺省才继承账号设置 |
| 首次自动供稿 | 账号策略产生本篇有效值，在提交前冻结 |
| 自动行进入生成 | 行字段缺省可从绑定合同补齐；行字段与合同冲突走已有输入变更机制，不拼出混合版本 |
| 已开始生成的续跑 | 使用原冻结输入；账号后续修改不改变进行中任务 |
| 需要换主题/商品/地点 | 走现有新任务或显式重规划入口，不在自动重试时暗改 |

只增加确有必要的内部结构字段；由程序维护，运营不填写 JSON。新语义使用版本标识并参与现有指纹；旧合同缺字段走窄兼容，不能按最新账号配置重算历史值。

## 三、Phase 1：先修自动运行与目的地闭环

### 1.1 在正确时机决定地点

修改：`packages/organic_photo_video/services/auto_photo_supply.py`、`material_adapter.py`。

- 定位优先且本篇确为旅行主题：在候选筛选和终选前，按已有范围轮换选出城市，放进 effective_brief。
- 参考优先：默认主题只是偏好；在现有一次终选中返回最终选题性质及允许范围内地点，不新增模型调用。
- 仅配置目的地范围不意味着每篇旅行。非旅行配色/通勤保持无目的地。
- 明确的本篇国家/城市作为相容组合解析；城市不属于国家时使用已有错误处理，不能将“日本+首尔”送入生成。
- 目的地进入实际终选 prompt，而非只在调用后写合同。环境用途才约束地点相容；穿搭用途不要求素材在当地拍摄。
- 具体旅行主题无可用地点：供稿阶段结束该名额并回写缺配置原因，不创建注定失败的生成任务。普通非地点主题允许地点留空。

### 1.2 生成入口读取同一目的地

修改：`services/feishu_workflow.py`、`photo_reference_vision.py`，复用现有 locale/copy 变量解析。

- 在 build_travel_topic 之前统一解析目的地，补齐自动行缺失的地点，来源为绑定的冻结合同。
- 恢复自动行“旅行地点（可选）”回显，填本篇已选城市；回显不是唯一执行依据，合同仍可补缺。
- 将业务城市名称和文案模板枚举分开：城市用于实际 place 与本地化标题；模板 token 继续走既有合法枚举。不能把原始“东京”直接塞入只接受枚举的字段，也不能用 generic token 覆盖真实城市。
- 封面/发布标题自然带入已选城市；内页不要求重复。中文回写由最终文案生成，摘要显示地点及来源。

### 1.3 未知提交按账号保护

修改：`services/auto_photo_supply.py`、`external_supply_contract.py`。

- 每轮先对账所有日期的 submitting，按合同原账号/日期/slot 找回记录。
- 对账后仍有未知提交的账号，本轮暂停新增供稿；保留既有任务续跑与对账，其他账号正常。
- 对账结果只保存一次，不同时把同一行计作可见库存和未知库存。
- attach_record 等失败按单合同捕获，保存原因和未知态，不使整批账号退出，不伪装补绑成功。
- 查询暂时为空或超时不等于远程没有创建，不能释放成可重新提交。
- 保留已有请求前提交意图、租约校验和额度预留，不换状态机。

默认库存 12 暂不借本轮修复静默改回 4；它是独立运营策略。测试使用账号级显式上限，不为绕过历史积压继续抬高全局默认。报告中列出受默认值影响的范围即可。

Phase 1 验收：

1. 账号“打卡穿搭+东京”→原始自动行→真实主题构造，无人工补地点；实际终选输入、合同和规划城市相同。
2. 本篇明确东京覆盖账号首尔默认；续跑时改账号范围仍保持东京。
3. target_inventory=1，首日已提交但响应/列表未知；次日仍不可见，远程总记录数保持 1。
4. 问题账号补绑异常，第二账号仍可正常执行；关掉自动化的账号只对账，不新增。

## 四、Phase 2：统一生成约束，消除内容冲突

### 2.1 视觉预设跨分支传递

修改：`services/feishu_workflow.py`、`photo_reference_vision.py`、`photo_style_reference_supply.py`。

- 在旅行/通用分支共享边界传入有效视觉预设，规划阶段已知道背景方式，规划完成后将同一快照写入 style_profile。
- 使用现有 background.mode/kind/fixed_scene_zh 等字段，复用已有 fixed 生图分支，不另造背景系统。
- 固定背景任务中的城市只影响搭配、场景用途与文案语境；不能让地标进入画面。
- 所有空白/未配置的历史输入保持原行为；不得因缺新字段全局强制纯色。

### 2.2 参考用途由页级合同决定

修改：`services/material_adapter.py`、`external_supply_contract.py`、`feishu_workflow.py`、`photo_reference_vision.py`、`photo_style_reference_supply.py`。

- selected_pages 的既有 purpose 在共享入口映射为允许用途；需要时在页内增加程序维护的 allowed_uses，继续沿用 OUTFIT/ENVIRONMENT/VISUAL_STYLE 等现有枚举。
- full_outfit/outfit_detail 表示穿搭，不自动附加环境；visual_tone 表示色调/摄影。ENVIRONMENT 只在现有采用语义明确需要并允许时加入，不能由模型看见街景便扩大用途。
- overall 是该页已允许用途的集合，不等于所有用途，也不统一缩成 OUTFIT。
- 对允许范围内的内容，模型分析可以提供描述或缩小实际采用范围；不能把未允许的环境变成生成依据。显式空用途与“未配置”分开处理。
- 补齐 plan_travel_content → _travel_planning_images 的参数传递；规划图片清单、生图角色/提示词和 QA 读取相同有效用途。
- 固定背景剥除 ENVIRONMENT 后仍可参考衣服和配色；narrative_only 不传外部图片，商品/人物图不受影响。
- 整图仍可能给模型带来背景干扰，先用角色/提示词解决；本轮不建设强制裁图流程。

### 2.3 商品事实与参考灵感分开

修改：`services/auto_photo_supply.py` 的主张及内容要求构造，和现有规划/product_context 接入点。

- 商品槽位的颜色、版型、材质与结构，使用既有商品参考和已确认属性。属性不确定则不编造，不能从商品标题正则猜出唯一变体。
- 参考中的配套单品、层次、比例与配色关系继续使用；指定商品槽位的原商品描述不再作为执行要求拼入 core_items/outfit_relations。
- 能结构化区分槽位就过滤对应槽位；无法可靠拆开的混合自然语言不原样注入执行要求。保留原文作来源记录，让既有规划调用基于可信商品信息和可用关系适配。
- 避免只替换 topic_statement、其余提示词仍说“奶油白为核心”。不要再堆颜色/材质正则，也不新增一次模型清洗调用。
- source_topic 保留原始“8种搭配”，最终主张与页数由实际计划决定；封面数字只统计实际呈现的造型或分组，4套对应3种公式需明确分组。
- QA 复用已有商品一致性检查。修正商品参考输入/判定条件，不新增审美评分门槛或多轮重生。

### 2.4 主题、温度和市场路由只解析一次

修改：`services/auto_photo_supply.py`、`material_adapter.py`，必要时调整现有主题变量解析。

- 定位优先尊重明确主题；参考优先默认主题只影响偏好，最终采用已支持的相容主题。
- 不能通过“旅行/出游”关键词自动选择凉爽旅行并产生 15–22°C。只有显式温度或用户明确采用的有温度含义预设才产生该温度，记录来源。
- 检查执行 profile 的默认温度是否又在下游注入：无温度的打卡内容不得在规划中恢复 15–22°C。修复限定新合同的明确语义，历史冻结 profile 不重写。
- 对确需温度的主题，供稿前从已有配置解析；缺少时明确缺口，不能随机补温度。无需实时天气。
- 非旅行路线保留显式温度；结构不支持则使用已有相容结构或明确报原因。
- TH 通用四选一回退仅用于 TH 女装。其他国家/类目走现有已支持入口；没有相容自动路线时跳过该任务并说明，不回退为 TH。

Phase 2 验收：

1. 固定背景＋外景参考：真实规划输入和生图请求均为 fixed，不出现参考街景要求。
2. 合同仅 OUTFIT、视觉分析返回三用途：最终用途仍仅 OUTFIT；同图明确采用穿搭＋环境时才能同时生效。
3. 指定浅蓝外套＋米白外套参考：完整最终执行要求无“以米白外套为核心”的矛盾，配套裙裤参考仍保留。
4. 参考优先＋默认凉爽旅行＋日常配色参考：最终不被强制旅行；旅行但未指定温度时，下游无自动15–22°C。
5. MX/VN/围巾相关输入不误入 TH 女装回退；旧冻结任务输入指纹和正常续跑不受影响。

## 五、Phase 3：素材消费与成片呈现收口

### 3.1 具体缺口与真实消费使用同一匹配规则

修改：`services/material_adapter.py`、`material_analysis.py`、`auto_photo_supply.py`、`scripts/export_material_gaps.py`。

- 从有效需求构造 demand：主题、实际需要用途、商品形态、国家/城市、地点使用方式。不得固定三用途/环境需求。
- 零候选、终选无合适素材、用途不兼容共用需求记录入口，沿用稳定 demand_key。
- 初筛与缺口满足共用轻量匹配函数；查询族总量只作统计，不能清除具体需求。
- 环境要求：排除明确异地冲突地标；无明显地点特征的普通街景可以兼容，不要求每张证明拍摄于东京。未分析素材不能当成已验证环境候选。
- 穿搭/色调要求：异地素材可用；固定背景不要求当地照片。城市搜索词仅是发现线索，不是全部候选的资格门槛。
- 只按需求相关可用候选判断缺口消退，沿用小数量阈值；不做复杂相关性模型。

### 3.2 搜索尝试与搜索命中分开

修改：`labs/xhs-material-lab/scripts/collect_by_demand.py` 及 lab 的既有 SQLite 迁移入口。

- query_hits 保留素材来源关系；冷却读取需求/查询的尝试时间，成功零命中也记一次尝试。
- 优先复用现有运行记录；若没有等价结构，才新增小型 search_attempts 表，保存 demand_key、query、state、started_at、finished_at、result_count、error。无需业务后台。
- 同需求同查询并发只允许一个有效尝试；成功后按现有24h窗口冷却，错误使用有限退避，不立即无限重试。
- 重复命中能关联当前需求，不能被旧唯一键静默丢弃；可用需求关联表或兼容迁移，不清历史 query_hits。
- queries 每需求少量组合：地点＋主题＋商品，保留通用搭配词；不做所有城市笛卡尔积。
- 采集仅写实验室库，不在生图进程同步抓取，继续保持采集/消费解耦。

### 3.3 每次供稿有限补分析

修改：`services/material_analysis.py`、`auto_photo_supply.py`、`scripts/run_auto_photo_supply.py`。

- 将零候选和不足三篇的两次补析合为一次；本轮执行共享最多5篇的补析预算，账号按相关需求分配，不每个slot再扩5篇。
- 只传本轮相关 note_ids；当前图片/所消费文本指纹＋模型/分析版本命中缓存则不调用。
- 素材改过但note_id相同，按当前指纹重新分析；未改素材复用缓存，不全库force。
- 继续共用已有调用数和输入图片数预留。没有足够候选则记录缺口并退出该名额，不反复换词/反复分析。

### 3.4 四宫格使用真实独立文字区

修改：`services/feishu_workflow.py` 的最终布局选择、`services/visual_preset.py`、`photo_structured_layout.py` 及实际四宫格底图拼合消费者。

- 从最终 layout_snapshot 判断生效配置，不能只改会被覆盖的 PHOTO_CHOICE_CARD_V2。
- 在现有结构化排版中为 grid cover 添加版式参数；只作用于四宫格，不改变旅行单图或固定背景单图。
- 建议初始值：上方图片区约占80%、下方文字区约占20%；文字区素色、左对齐、主标题最多两行、可带一行说明。实际比例可按现有画布和泰文字号有限调整，不作为全业务规则。
- 四张底图按图片区等比缩放/适配，尽量保全身与鞋；文字不能与图片框重叠。不做“文字挪到底部仍压着腿”的假留白。
- 使用现有泰文字体与换行能力；溢出按已有规则处理，不无限缩字、不静默删文案。
- 解释类选题复用规划结果给每页一句简短搭配理由；纯灵感内容不强制长说明。封面承诺的公式/对比必须在内页找到对应内容。
- 中文继续从最终发布/渲染文字回写，不能展示规划草稿的旧版本。

Phase 3 验收：

1. 通用旅行库存充足、所需环境仍不兼容时，具体需求继续导出；只借穿搭时异地素材可满足。
2. exporter实际输出被collector消费；空结果、重复命中两次运行均遵守冷却，需求来源关联不丢失。
3. 零候选补成1–2篇后不再第二次补析；无关note不被调用；同ID更新素材指纹会刷新。
4. 通过正式模板选择渲染四宫格：检查文字区/图片区bbox不相交，直接查看输出；测试不能手工给模板注入一个生产未使用的参数。

## 六、测试与样片验收安排

先增加能复现审查问题的集成失败用例，再修改实现。外部模型/飞书/搜索用 mock，核心调用者和消费者使用真实代码。既有194项相关测试作为回归基础；有新影响再补对应市场、账号同步和冻结兼容测试，不以全量测试数字代替链路证据。

离线通过后，仅做以下真实验证：

| 编号 | 输入与路径 | 验收重点 | 成本 |
|---|---|---|---|
| A | 账号定位旅行；东京；指定浅蓝商品；旅行场景 | 不补字段直接生成；商品真实一致；城市进标题；四搭有差异 | 1套新图 |
| B | 参考优先或明确通用主题；纯色；异地外景素材仅借穿搭 | 纯色真正生效；不强行旅行/温度；参考搭配仍有作用 | 1套新图 |
| C | 既有配色底图＋最终四宫格模板 | 真留白；不压脸/腿；说明回应封面；中文一致 | 只重排，0次生图 |
| S | 一个真实具体需求，最多2–3个搜索词 | demand→搜索尝试→query_hits→分析→候选匹配/消退 | 小批采集分析 |

真实模型可能不选中新抓素材：如实保存未采用原因，不强制用劣质素材来“证明闭环”。但必须证明其进入可消费候选链。采集有结果不等于已分析可用；生图出现东京不等于采集命中东京。

证据复用现有 manifest/测试报告：代码版本、记录ID、有效需求、实际prompt摘要、冻结合同、每图用途、最终layout_snapshot、成片、中文回写和调用数量。可取得provider/model/request_id则记录；不能拿自造任务名冒充供应商原生请求ID。

抽样是本次开发验收，不变成日常逐篇人工审批。自动发布继续沿用既有授权机制，本轮不顺带放开。

## 七、实施与交付要求

- 三个Phase分别提交；Phase 1可先交付，Phase 2依赖统一输入，Phase 3复用前两批的有效需求。
- 增量迁移要幂等；SQLite新状态/字段默认兼容旧记录。仅搜索尝试没有等价存储时增加小表，不新增飞书业务表。
- 修复只作用于新任务或已有明确恢复路径；不批量改历史冻结合同、不删除失败样片、不自动重跑已付费任务。
- 运行中任务保持旧快照；需要重验的旧失败行使用现有重规划/新任务机制，留下对照。
- 最终交付列“已验证/未实测/剩余问题”，附真实输入到输出的证据。不得仅写“全部测试绿/已产出图片”即宣告完整验收。
- 本轮完成标准：A/B/C/S验证通过、关键故障用例通过、现有稳定入口无回归。此后再考虑扩大自动供稿范围。
