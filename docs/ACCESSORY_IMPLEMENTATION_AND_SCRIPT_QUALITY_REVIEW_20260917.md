## 3. 当前实现的确定缺陷

### I1. [P2] 生成后判成重复，仍作为 READY 交付

`core/original_batch_executor.py:1693` 计算重检结果，随后只写入 script；`:1760` 返回 SUCCESS；`:1166` 根据 SUCCESS 标记 SCRIPT_READY。生成及同步链路未发现消费该失败裁决的其他逻辑。

离线 mock 真实 `run_script_only`：执行结果含 `review_status=EXACT_DUPLICATE, counts_as_independent=false`，实际状态仍为 `SCRIPT_RUNNING → SCRIPT_READY`。因此新增报告目前不能保证“完成数”就是“足够不同的可用脚本数”。

建议：精确重复至少从独立可用数与自动候选集合中排除，记录具体处理状态；其他不确定的创意相似性可以继续人工复核，不必扩大成无界模型重写。

### I2. [P2] 不同商品互相耗尽 A/B/C 模板

`core/original_batch_executor.py:822` 按国家/类目读取近期 120 条；`core/original_batch_allocator.py:1754` 转换历史参考时没有按当前 product_code 过滤，混合视觉签名又没有商品身份。

纯函数复现：OTHER_SKU 的耳饰 A/B/C 进入历史后，SKU_NEW 即使主题和 claim 不同，也可三个模板都被 EXACT_DUPLICATE 排除。

建议：同商品做内容硬去重；跨商品复用模板属于账号风格/排期判断，不可直接等同于重复成片。

### I3. [P2] “实际正文复核”仍混入冻结计划差异，且没有跨批正文比较

`core/accessory_mixed_templates.py:2420` 用冻结单元构造视觉签名，再附加 visual_content；digest 仍包含 template_id、计划观察任务等。两份四段 visual_content 逐字相同，只关联不同 A/B 模板，仍返回 EXECUTION_VARIANT、counts_as_independent=true、FINAL_SHOTS_DIFFERENT。

同时，`core/original_batch_executor.py:1696` 只传同批兄弟条目；历史台账保存规划签名，完成后未保存实际正文签名。当前没有实现实际正文跨批复核。

建议：计划签名与成稿签名单独存储；成稿比较基于实际可执行分镜、动作和对应观察意义，不能以计划 ID 差异抵消正文相同。复核同时读取同商品本批与历史成稿。

### I4. [P2] 15 秒冻结合同可以渲染成 12 秒时间轴

`core/accessory_mixed_templates.py:1842` 投影到 storyboard 时不写 time_range；`core/production_script_renderer.py:543` 又用 storyboard 时间覆盖冻结单元时间。

复现：storyboard 为 0–3 / 3–6 / 6–9 / 9–12 秒，投影 APPLIED 且校验无错；冻结单元是 0–3 / 3–6 / 6–10 / 10–15 秒，最终渲染末镜却仍为 9–12 秒。

建议：时间轴从冻结合同单向派生到 storyboard，并在最终提示词前验证；不能只验证 capture_units。

### I5. [P2] 未确认结构被错误授权为可展示部件

`core/accessory_mixed_templates.py:609` 使用有限否定词和正词子串判断。

复现：`resolve_part_evidence('has_clasp', anchor_texts=['搭扣结构无法确认'])` 得到 VERIFIED，随后动作增加“已确认的搭扣外观与连接位置”。

建议：优先明确结构化证据，保留 UNKNOWN；“无法确认/看不清/未提供背面”等不能被正词匹配提升为事实。

### I6. [P2] 仅第一镜有锚点时仍提升为全片要求

`core/video_prompt_compaction.py:515` 只判断出现过的锚点值是否唯一，没有验证每镜都声明相同要求。

复现：第一镜要求背部耳针连接处，第二镜为佩戴正面且没有锚点字段。超长压缩后变成“每段商品必须可见：背部耳针连接处”，report.ok=true，审计无错。

建议：所有镜头均有且相同才提升；缺字段不能视作相同。

另有两个未列入上述确定复现的验收项：并发历史读取→分配→预留缺少排他性检查，现有测试只验证插入不丢行；文档自报发卡/头绳等别名的类型回退问题，本次 25 条的表中名称为发夹/抓夹，未以真实样本证明触发该别名问题。

## 4. 正式产物没有用上新混合模式

25 条全部无 mixed_template_contract，mixed_difference_report 与 mixed_final_shot_recheck 为空。逐条分镜均围绕已佩戴发饰推进，没有形成每条同时包含独立手持、台面静物、佩戴效果的模板组合。

全库 679 个 item 中未查到混合合同，609 条所查创意历史中 mixed_signature 为 0。已检查的 shell、工作区环境及相关启动配置没有发现启用变量。这里只能确认“所查运行产物未启用”，不推断其他未知进程的环境。

因此，首要上线工作不是直接再批量生成，而是修好 I1–I6 后，用一条明确启用的新规划确认：任务作用域 → 冻结合同 → 模板版本 → 光线快照 → 最终提示词 → 差异报告均确实存在。不要给旧任务补一个标签就当成新版。

## 7. 下一步优先级

1. 先处理实际输入冲突：确认褶皱发饰结构；核对框体插杆、黑色边夹的运营卖点。给“商品身份 vs 运营卖点”增加明确冲突结果，不能由 soft_only 自动绕过。

3. 用一款抓夹、一款边夹、一款结构已确认的褶皱发饰验证不同物理类型，确认每条真的有手持/静物/佩戴、镜头不露脸、一个冻结光线配方。
4. 首饰类补耳饰/腕饰/戒指真实新脚本样本后再分别验收，不沿用发饰结论。先做小批，再扩大至 10–20 候选。
5. 文案按外观审美、佩戴比例、具体使用问题分配主线。每条增加与主线对应的观察任务，合并同义稿；缺证据时减少产出。
