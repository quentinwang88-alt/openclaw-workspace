## 3. 必须处理的问题

### R1 · P1：最终渲染仍把手持／静物动作改回人物佩戴动作

位置：`core/production_script_renderer.py:577–584`。旧 `unit_role` 仍决定 `core_action` 和 `movement_guidance`，没有服从混合模块自己的载体与动作边界。

独立重渲染四条真实新稿后，**4/4 稿受影响，8 个非佩戴镜中 5 个出现冲突**。例如 SCRIPT_E45E858EB0C623BE5196 的 CU_02：

- 模块：STATIC_PRODUCT。
- 正确原分镜：人物不入画，商品全程静置。
- 最终动作却变为：人物在颈肩关系内自然改变一次重心或轻微侧移，下一段重新放置手机补录发饰结果。

同稿的手持镜也被写入肩部、头部变化。提示词同时要求纯商品／纯手部与人物佩戴动作，视频模型收到相互冲突的执行要求。生成前的合同检查无法发现最后一步的覆盖。

修复：混合模式以每镜 module、carrier_mode、允许身体部位、成稿动作作为最终权威；旧佩戴动作弧不得再覆盖手持与静物。同步检查角色名、商品关系、手机构图、末镜结束指令等消费者，不能只删掉一行人物动作。旧纯佩戴模式保持原行为。

验收：四条现有稿离线重渲染即可，先做到全部非佩戴镜零人物佩戴动作；静物不得移动，手持不引入肩颈头部；时间轴与锚点不回退。修好前不建议把这四份最终提示词直接送视频生成。

### R2 · P2：背景换词被误判成独立脚本

位置：`core/accessory_mixed_templates.py:2542–2550`、`:2713–2735`。

成稿视觉签名对整段 visual_content 做文本 hash，新的成稿镜头记录不含 observation_job；比较器拿不到新的观察任务后，直接把文本不同解释成 SHOT_ORDER_DIFFERS。

边界复现：商品、动作、镜头顺序完全不变，只把四镜中的“浅木”改为“灰色”、配方改为灰色，得到 EXECUTION_VARIANT、counts_as_independent=true、SHOT_ORDER_DIFFERS。实际没有调整镜头顺序或增加商品信息。

影响：仍可能靠环境换皮累计所谓独立稿，不能据此支持同款 10–20 条有效差异的目标。

修复：从成稿提取实际展示对象、可观察信息、动作／状态和顺序；背景、光线、措辞独立归为表层变化。只有顺序集合确实重新排列才报告 SHOT_ORDER_DIFFERS；无法确定时标记待复核，不直接计为独立。不要重新把计划模板 ID 加回正文签名。

### R3 · P2：中断恢复可能把脚本自身判成重复

位置：`core/original_batch_executor.py:1450–1458`，成稿签名先写台账的调用在 `:1908`。

历史过滤只检查同商品，没有排除当前条目。若成稿签名已写入 RESERVED 台账，而 READY 结果尚未持久化时中断，恢复后可能把当前条目自己的签名纳入历史。

纯函数边界复现：传入当前 I1 已带成稿签名的 RESERVED 行，得到 references=1、nearest_script_id=I1、EXACT_DUPLICATE，状态被分流为 SCRIPT_DUPLICATE。**这不是四条新稿已经发生的问题，而是可复现的恢复边界缺陷。**

修复：按稳定条目身份／creative_usage_id 排除自己；对同批兄弟与历史重复引用做去重；保留其他条目的跨批比较。补“写成稿台账后中断、恢复同条目”的幂等测试。

### R4 · P2：同商品事实被误当同主题

位置：`core/accessory_mixed_templates.py:2237`，主题输入来源见 `core/original_batch_allocator.py:1918`。

semantic digest 使用 claim/evidence ID、观察词及结构，没有比较成稿的实际购买理由和口播语义。两条脚本复用同一商品事实，即可能被认定同主题。

本批实际证据：

- 蝴蝶 A 谈多场合搭配，B 谈双层蝴蝶的柔美外观，两者 semantic digest 均为 cb8f6f789066fa11b60f。
- 花朵 A 谈花瓣轻柔氛围，B 谈省步骤与蓬松丸子头，两者均为 582695e92cb6d50b3897。
- 两个 B 均报告 SEMANTIC_IDENTICAL / EXECUTION_VARIANT。该结果只能说明复用了同组商品信息，不能证明真实表达主题相同。

修复：商品身份／证据签名与内容主题签名分开；主题取成稿中的核心购买理由、观察角度和表达意图。测试“相同事实不同主题”以及“不同措辞相同主题”，不能用不同 ID 直接代表不同主题。

### R5 · 内容问题：花朵 B 的口播效果没有落实到镜头

脚本 SCRIPT_36BA1FA151ABD1ED3638 的中文回译：“随手一夹，我就觉得丸子头看起来蓬起来了，不用费心做复杂造型。”

实际分镜只写了固定发束、整体通勤发型和微卷发丝；没有明确丸子头形态，更没有支撑“一夹完成、省步骤”的过程。operator 卖点提供了写作方向，不等同于真实个人使用体验已经被验证。

建议优先缩窄到可见结果：先确认适用发型和产品事实，再明确已经完成的蓬松丸子头、夹子位置和侧后方轮廓，口播只谈画面能展示的视觉感受。不要为证明“一夹完成”强行加入高风险夹合过程；没有证据时直接移除省步骤与实测口吻。

这是前一版 P1/P2 商品事实与镜头口播统一工作尚未完成的具体例子。

当前主要改善是展示方式更丰富，商品观察重点仍较通用。手持和静物经常都在重复“轮廓、层叠装饰、反光点”，模板拥有不同模块，不代表每个模块已经带来不同的信息。

推荐结构：一个核心购买理由 → 各镜承担不同但相关的观察 → 一段自然的整体口播。沿用女装经验，固定合同不固定创意内容；直接切镜允许状态变化；最终渲染不能覆盖已经正确的动作；生活感镜头可以服务氛围，不要求每一镜都证明功效。
