## 1. 背景、现状与完成目标

账号预算自动供稿、素材抓取／消费、商品与人物参考、旅行与固定背景生成、中文回写、原生图文发布均已有实现。最新代码新增两个主题与讲解配置，但真实记录 `recvvDtJs32UnL` 等仍出现：主题是攻略、旅行 topic 为空、文案回落选择 A/B/C/D。新 narrative_plan 没有驱动下游；参考依据没有完整持久化；四宫格文字没有进入预留区。

因此“成片像四套展示”首先是执行链路问题。其次，当前参考分析主要概括衣服、颜色和造型，而教程需要提取“为什么这样搭、怎么照做、哪一页证明”。只把标题改成攻略，或者给展示图加一句理由，仍不足以形成教程。

目标：读者在图片上就能理解一条可执行方法，画面能支撑说明；不同篇围绕不同问题组织内容。参考小红书的编辑方式和信息价值，不复刻其人物、原文、品牌或整组版式。

边界保持：

- 不新增运营必填列、JSON维护、逐篇审核或新生产入口；账号预算与现有发布授权规则不变。
- 仅启用 TH 女装的 TRAVEL_STYLING_GUIDE、COLOR_TUTORIAL。既有四选一、打卡、一衣多穿、MX 假发、VN 围巾和视频保持原流程。
- 保留四个源角色 look_a/b/c/d、四张教程成片，look_a 直接承担封面；不增加第五张重复封面。
- 不切换模型，不新增多轮审美评分；沿用既有规划调用、Doubao 素材分析与有限修复预算。
- 不修改历史冻结任务、批量清缓存或重跑已有付费图片。

## 2. 先规定成片该有什么，再接程序

### 2.1 旅行攻略：围绕一个实际穿搭问题

首批示例：“东京走一整天，长裤怎么搭得利落？”这里东京是使用语境，不代表已查询当地天气，也不要求每页换地标。

| 页 | 读者获得什么 | 画面任务 | 图上中文含义示例（发布时生成泰文） |
|---|---|---|---|
| 1 | 本篇问题和整体效果 | 一套完整、好看的商品穿搭 | 东京步行穿搭：长裤怎样穿得利落？ |
| 2 | 裤脚如何衔接鞋 | 全身图能看清裤脚；有足够清晰度可附同图局部 | 裤脚轻盖鞋面，别堆在鞋口 |
| 3 | 上下比例如何调整 | 短外套／明确腰线与裤长关系可见 | 上身收短，让长裤线条更完整 |
| 4 | 配件怎样收束造型 | 同商品搭配中的鞋包色彩关系可见 | 鞋包选相近颜色，减少零碎感 |

这是示例，不是以后每篇固定的三条。模型要结合账号定位、商品与参考，确定适用的两到三条方法；第四页也可以总结前两条，不强凑第三条。

涉及舒适、保暖时，不把图片无法证明的材料性能写成商品事实。例如没有实测依据不写“走两万步不累”；没有温度输入不自动填 15–22°C。无需新质检系统，放进既有商品事实与文案约束即可。

### 2.2 配色教程：解释颜色关系，不只是换颜色

示例：“浅蓝外套怎么配，才不会全身发灰？”商品必须真实提供浅蓝款时才采用；否则根据绑定商品事实换问题。

| 页 | 内容 | 画面与版式 |
|---|---|---|
| 1 | 问题＋一套完整效果 | 主图、简洁标题；不四宫格、不投票 |
| 2 | 奶白靠近脸部：让浅蓝与肤色之间有亮色过渡 | 可见的奶白内搭＋浅蓝商品；颜色名对应单品 |
| 3 | 深灰放下半身：建立明暗层次 | 浅蓝商品＋深灰下装；短解释＋两三块示意色 |
| 4 | 棕色少量呼应：集中在鞋包 | 商品颜色不变；鞋包呼应清楚；总结适用方法 |

允许四页同一商品、相似场景、部分相近搭配。教程的差异来自论点与证据，不要求裤／裙、动作、背景、轮廓全部不同。色卡是示意，不能伪装成商品实测色值；不能强制所有教程都用奶白、深灰、棕色。

### 2.3 怎样避免所有篇再次长得一样

优先变化“本篇问题→方法组合→证据呈现”，保持账号视觉基调稳定。复用现有历史记录，把近期少量内容的问题／方法简要传入本次规划，作为软性避重复提示；无历史即跳过，不增加模型调用和拒绝阈值。

不靠随机换标题、城市和背景制造差异。旅行攻略与配色教程应有不同的信息主线；同一个教程内部也不能四页都是“全身模特＋造型名称”。

## 3. 架构与配置优先级

链路：

```text
账号默认配置／预算 + 本篇显式覆盖
                  ↓
归一 effective_brief（主题、商品、地点、背景、账号风格、语言）
                  ↓
素材消费：选择参考方法与语义页 + 按用途选择图片
                  ↓
外部供稿合同冻结：effective_brief.reference_basis
                  ↓
既有规划调用：公共合同 + 讲解规则 → 每篇 narrative_plan + looks
                  ↓
生图消费页级视觉任务 → 最终文案归一／语言修正
                  ↓
冻结 request：四页 content_card + 文字／布局／来源快照
                  ↓
程序排版 → 同源中文回写 → 现有发布流程
```

仍复用两个现有生产预设。生产预设提供执行能力；主题决定讲什么；视觉预设决定场景／室内／纯色及账号基调；版式决定画面和文字如何摆。不要让“旅行”强制室外，也不要让“四选一”入口名称强制新教程投票。

优先级：本篇显式主题／商品／视觉设置 > 账号有效默认 > 允许的自动推导。商品已指定时，参考不得替换商品。账号“自动”归一为未指定，保留字段来源；冻结后只读快照。

在现有主题解析处集中增加执行能力解析，例如 `resolve_theme_execution(theme, market, category)`，输出内容模式、讲解类型、是否使用目的地范围等。不要在供稿、规划和排版分别维护一套 theme_key 判断，也不要给教程硬塞旧旅行类型。

旅行攻略使用账号目的地范围时，在选材前确定本次目的地；本篇指定地点直接优先。未设置地点且问题并不依赖具体城市，可做通用旅行攻略，摘要注明未指定，不凭素材文字猜城市。配色教程默认无地点要求。明确固定背景时，地点仅进入内容语境，环境参考不得覆盖背景。

## 4. Phase 1：修复入口和冻结，先保证需求不丢

### 4.1 账号与恢复

模块：发布器 `app/scheduler.py`、`run_pipeline.py`；OPV `publish_account_profile.py`、`auto_photo_supply.py`。

- 统一“指定商品编码／默认产品编码”读取与建字段兼容：优先新字段，旧字段作兼容，不重复创建两列、不覆盖旧值。两者明确矛盾时输出来源冲突。
- 保留已修好的填码推导 specified、“自动”前置归一、账号风格继承。

- effective_brief 中温度缺失保持空；显式温度是内容条件，不声称实时天气。检查执行 profile、旅行文案 fallback 不再给新教程补默认温度。

### 4.2 参考依据真正落库

复用现有 external_supply_contract.effective_brief JSON，新增可选的 `reference_basis`，不增加业务表或运营列。

建议最小内容：来源 note_id、analysis_version、语义采用页 seq、借鉴的方法、画面证据、允许用途。只存选中内容，不复制整篇分析。

语义采用页与 selected_pages（实际上传的图片）是不同概念：narrative_only 可以有讲解依据、没有图片；配色可借鉴文字方法，但环境只能来自获准 ENVIRONMENT 用途的图。

更新 persist／supersede／read round-trip 和新合同指纹。新版本指纹纳入有效需求与参考依据；旧合同继续按旧版本读取，不补写、重算或否定既有已创建任务。

验收：从实际账号行解析到供稿合同再读回，主题、商品、地点和参考方法均不丢；空渠道不抢配置；attach 异常时第二账号仍处理。

## 5. Phase 2：把小红书素材变成可消费的教程资产

模块：`material_analysis.py`、`material_adapter.py`、`auto_photo_supply.py`、`external_supply_contract.py`。

### 5.1 分析只补关键缺口

保留 outfit_summary 等现有字段，给页级分析增加可选的讲解信息：

- 本页明确讲了什么方法／论点；
- 对应的可见画面证据；
- 页面职责：提问、解释、示例或总结。

如果只有好看的搭配照片，没有方法信息，就保持为空。不能把“米白上衣＋灰裤”自动当成已经验证的教程，更不能编造来源说过的结论。区分“来源明确讲解”和“本次根据画面重新提炼”；后者由规划形成自己的说明。

继续使用当前 Doubao 分析调用；新版分析增加版本指纹。优先处理本轮候选中少量最相关素材，复用已有单批上限，不重分析全库、不新增一遍独立模型审稿。文字型页可作为叙事依据，是否可用于生图另行判断，不能因文字多就统一判叙事不可用。

### 5.2 选材规则必须清晰

| 条件 | 怎么用 |
|---|---|
| 明确旅行攻略＋城市 | 先匹配本篇问题与场景；需要环境时才提高同城图优先级。泛用裤脚教程不因没有东京建筑而被淘汰 |
| 明确配色教程＋商品 | 优先颜色关系／方法适配，不要求参考同款；商品颜色与版型由自有产品资料负责 |
| 只有合适穿搭图，没有教程文字 | 作为视觉例子；规划基于可见关系形成原创方法，不伪造来源依据 |
| 有方法、原图不适合上传 | narrative_only，保留方法与证据页编号，零图片输入 |
| 找不到合适素材 | 只有既有原创能力能在当前输入下生产时，沿原无参考路径做教程；否则账号槽位记录缺口。不能静默降为投票或自动扩大抓取范围 |

采用页必须来自终选结果，不能固定取笔记前四页。指定商品时，将方法适配到商品：如参考“亮黄外套当主色”，仅借鉴主色分配方法，不继续把亮黄外套写进执行要求。无法可靠拆分的商品句不注入，保留源记录即可。

把参考方法作为结构化字段传规划，不拼在长字符串末尾再截前 200 字。选题、商品、方法、地点和背景分别控制长度，必需字段完整保留。

本轮不依赖抓取端新增大功能；已有搜索词若只偏 OOTD，可小幅加入“外套配色／同色系层次／旅行长裤鞋子搭配”等自然词，城市词按实际目的地需求组合。搜索增加候选不能代替消费链路修复。

## 6. Phase 3：真正让讲解规划驱动生图与文案

### 6.1 复用配置、消除死代码

模块：`photo_theme.py`、`feishu_workflow.py`、`photo_reference_vision.py`、`photo_content_planner.py`；复用 `TH_GUIDE_TUTORIAL_V1.json`。

- 两个真实入口都从有效执行上下文进入讲解规划，不能只在 travel_topic 上猜主题。
- 配置中的“浅色衔接／明暗对比／局部呼应”改成例子，而不是每篇固定方法；统一四页职责即可。
- 接通并统一已有 guide helper，去掉“未被调用的 helper＋另一处事后拼 narrative”的双轨实现。
- 提示组成：公共输入／商品人物背景合同＋唯一的讲解业务规则＋完整 JSON 输出 schema。禁止 guide_block 整体覆盖公共提示。
- 新教程适度放松原四选一差异规则：允许相近造型和重复商品，不以四套轮廓变化作为门槛。保留商品、人物、背景和明显畸形等原有质量规则。

### 6.2 每篇自己的 narrative_plan

在既有规划响应的每个 post/item 上返回以下最小结构，而不是从 posts[0] 的旧文案反推：

| 字段 | 用途 |
|---|---|
| version、kind、question_zh | 讲解版本、类型、本篇具体问题 |
| takeaways | 两到三条可操作方法；由本篇输入决定 |
| pages[].source_role | 与 look_a/b/c/d 一一对应 |
| pages[].page_role、key_point、visual_basis | 这一页讲什么、画面要证明什么 |
| pages[].text | 发布语言的 kicker/headline/body/cta；按需为空，不强填所有层级 |
| pages[].color_chips | 可选：颜色、单品角色和显示名称；颜色参照本篇 look 配色 |
| reference_basis | 引用已冻结的采用依据，允许原创无来源，不硬编码空串掩盖丢失 |

衣服款式仍由 looks 持有，不在 narrative_plan 中再保存可独立修改的整套衣服描述。页级视觉要求进入实际生图合同：讲裤脚就让裤脚与鞋清楚可见；讲领口提亮就要内搭可见。不能只留在内容摘要。

同款不同搭配可以生成四张图，也可以在一页用该页图的局部裁切强调细节；首版不引入不同页跨图拼接和服装抠图。保留既有四源图上限，不为局部裁切多调生图模型。

### 6.3 下游契约必须同时改

模块：`photo_theme.py`、`photo_request_factory.py`、`photo_content.py`、`domain/photo_contracts.py`、`photo_copy_review.py`、`copy_translation.py`、`feishu_workflow.py`。

- 教程原生构建四页 content_card 和四页文案；跳过旧的五页生成／删重复封面过程。旧 `apply_travel_single_cover` 保留给旧任务，不让新四页合同误入该函数报错。
- `build_theme_copy` 对版本化教程结构建立明确分支，不再因不是五段 slide_texts 而回退标签＋投票。
- 最终文字只有一个编辑源：规划 text 经现有语言修正后冻结为页面文字；slide_texts 是兼容投影，渲染、检查和中文翻译均由最终页面文字派生，不允许两份文案各改各的。
- 顶层 title/caption 与页内问题和方法一致；封面说三种方法，内页就必须有三种，不能沿用参考“8套／18种”。

- 语言修正失败保留图片，只走既有有限文案修复；不能兜底成投票，也不因为文字问题重新生成全部图片。
- 冻结并透传执行、规划、布局版本；新旧缓存隔离。多个 item 各自冻结各自叙事，不能共享第一篇。

验收必须截获真实模型调用前的 prompt，检查商品、地点、背景、方法和 JSON schema 都在；只测试 `_guide_plan_prompt_block` 不够。

## 7. Phase 4：用少量版式做出教程感

模块：`photo_package.py`、`photo_structured_layout.py`、`visual_preset.py`、`photo_request_factory.py`。

### 7.1 一套基础讲解版式，色卡作为扩展

不新增模板库后台。复用 clean／scene 两种现有视觉表现：

- 封面：一张完整造型＋清晰问题，必要时一句总原则；不强制四合一。
- 内页：主图约占 70%–78%，其余为有边距的解释区。比例是默认设计值，由画布和文字度量适配，不是生图质量门槛。
- 固定背景：主图与信息区使用同一底色体系；场景背景：图片完整放在主图区，文字区使用账号配色的简洁底色，避免直接压在人脸、商品上。
- 配色页在信息区增加两三块小色卡及对应单品名；不额外开一套模板，不生成无关装饰色盘。
- 一页默认“短标题＋一句怎么做／为什么”，末页按需总结。不强迫所有页都带 CTA、地点、编号或副标题。

优先处理文字层级、区域和泰文真实断行，沿用现有可用字体。不照搬中文小红书宋体，不靠无限缩小字号塞长句。生图模型负责干净画面；文字与色卡由程序排。

局部裁切是可选增强：原图清晰且目标部位可见时，用同图的小区域加强说明；否则用完整图解释，禁止模糊放大或凭空补出商品细节。本轮可先只交付主图＋解释区＋色卡，局部裁切不作为上线依赖。

### 7.2 修旧四宫格，不影响其余页面

四宫格 cover 的文字明确绑定已预留底部区域；仅该页覆盖位置，不能全模板 text_position=bottom 连内页一起改。利用已有图重渲染，检查标题不压人物且底部留白实际承载文字。

### 7.3 颜色与证据

账号色调统一仍沿用账号视觉基准，不把商品颜色也统一成背景颜色。色卡根据本篇商品／look 颜色生成示意，绑定对应单品；不建立新像素测色系统。沿用已有图像质检调用检查明显“文案说灰裤、实际蓝裙”等冲突，轻微色温和色差只记录，不重启反复重生。
