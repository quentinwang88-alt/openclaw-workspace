# TH 原生图文生产操作说明（2026-09-06）

当前新任务使用 `PHOTO_TH_PICK_YOUR_LOOK_V3`；V1/V2 与旧穿搭视频流程保留，只用于历史任务续跑。

## 运营只维护这些字段

1. `生产预设`：选择“图文｜TH｜穿搭四选一”。
2. `生成篇数`：填写 1–9。
3. `图文主题`：选择秋季穿搭、凉爽旅行、日常通勤或咖啡约会。
4. `参考图类型`：商品参考、风格参考或完整穿搭。
5. `参考图（可选）`：按下述模式上传图片；已有产品编码时也可以填写 `产品编码`。
6. 勾选 `执行` 生成预览；确认五页成品后勾选 `确认发布`。

运营不维护 Recipe、AssetSet、图片角色、哈希、Prompt 或 JSON。

## 三种参考模式

### 商品参考

上传 1–3 张同一外套的清晰商品图，或填写已有产品编码。系统保持商品外套不变，为每篇规划四套不同的内搭、下装和鞋履，再调用现有穿搭生图能力补齐 A/B/C/D。

### 风格参考

上传 1–3 张能够表达整体审美的参考图。参考图约束色彩、层次和氛围，不会被当成待发布成品。系统仍会先规划每篇具体的四套服装，再生成完整 Look。

### 完整穿搭

当外部已经有完整成品时使用。每篇上传四张，顺序为 A/B/C/D；生成三篇需要十二张。系统不重新生图，只排版和生成图文文案。

## 批量差异规则

主题和预设会先生成并冻结整批内容计划。每篇明确记录：

- 内容方案族与配色；
- A/B/C/D 的外套、内搭、下装和鞋履；
- 纯色背景；
- 泰文封面、发布标题、正文与 CTA。

系统在生图前检查不同篇是否重复使用同一方案族或完整穿搭；生图后检查同篇及跨篇是否出现完全重复图片。冻结计划保存在任务本地清单，并随生产批次写入 RDS，重试不会重新随机。

V3 不再强制 B/C 使用同一款外套。商品参考模式中的四套 Look 都保留同一目标商品；风格参考模式允许四套外套各不相同。

## 与穿搭模板库的关系

穿搭模板库提供人物模板、构图能力和兼容的基础 Look；图文内容计划决定本批次实际生成什么。新计划会覆盖基础 Look 中的内搭、下装、鞋履和风格方向，商品参考图继续作为目标外套的真实依据。

符合相同计划签名的历史成片可以复用；只有品类或裤裙类型相符、但具体服装不相符的旧图不会被硬套进新内容。新生成并登记的素材会带计划签名，后续同方案才能安全复用。
