## 上线前必须解决的 P1

### 1. 失败素材会堵住恢复入口（已复现）

`services/hero_first.py:358`：非锚点失败仍进入 image_review；`services/feishu_v2.py:112` 要求完整选中素材才能构建 snapshot。重试和返工入口 `:250`、`:280` 又都先读取 snapshot。

纯内存模拟 P4 生成失败：首次、重做 P4、重试审核均报缺少 `shot:4`，无法重新生成。技术 QC 失败的成片也存在相似门槛：进入 video_review，但预览只接受 QC 通过成片。

修复方向：允许读取不完整任务状态；先恢复失败槽位/渲染，再构建可审核快照及 token。区分重试生成、续跑审核、强制重审。

### 2. 批量中断会静默少产（已复现）

`services/feishu_workflow.py:312`：存在任一 V2 子任务即直接续跑已有集合；`:362` 逐套创建。模拟要求 3 套、已有第 1 套，恢复时创建次数 0，最终只处理 1 套。

修复方向：冻结批次 manifest/预期子任务 IDs；恢复必须补齐缺失项；整行完成条件包含 expected_count，不能仅看已有任务是否完成。

### 3. 返工版本存在半提交窗口（已复现）

`services/workflow_v2.py:535` 先激活 revision，再切 rework_pending 并更新投影；`repositories/rds_repository.py:597` 已先提交激活。模拟在两步间崩溃，得到新 active revision + 旧 video_review；恢复报当前版本没有可审核成片。

修复方向：激活、恢复阶段及必要投影同事务，或通过持久化 operation/outbox 幂等补全。

### 4. 实际发布路径提交超时可能重复发布（代码风险，未触发真实提交）

真实路径是 `scripts/run_feishu_tasks.py:61` → MainScheduleBridge → `skills/short-video-auto-publisher/app/scheduler.py`，不是 OPV 自带旧发布器。

主排班器 `scheduler.py:783` 提交；`:788` 异常释放占位；`:553` 将网络/超时归入重试。`app/neobund_publish.py:834` 只有正常响应缺任务 ID 才走后续远端查找，抛超时直接退出。如果远端成功而响应丢失，下轮可能重复提交。

修复方向：提交结果不明进入 ambiguous/submitting；先按业务标识远端对账，禁止直接重发。该项涉及真正外部副作用，必须在无人值守发布前处理。

### 5. 扫描与回写缺少可靠中断恢复（代码风险）

`scripts/run_feishu_scanner_locked.sh:6` 用目录锁，仅 EXIT trap 清理；SIGKILL/异常关机可能留锁，后续全部 exit 0。当前没有观察到遗留锁。

`services/feishu_v2.py:258` 先消费命令再处理；硬中断会留下生成中，普通扫描不自动恢复过期任务。飞书回写失败后外层异常处理还调用同一客户端，可能中断整轮。

修复方向：PID/租约锁、运行心跳、超时任务诊断与安全续跑、独立回写 outbox。不能只看进程 exit code 判断健康。

### 6. 发布队列未完整保留已验收版本约束（代码风险）

飞书入口有强校验，但 `services/main_schedule_bridge.py:136` 主要核对指针/ready/文件存在；`:159` 传主队列的 context 缺完整 release_revision/render/review/hash 清单。入队后文件变更，上传前无法统一验证。

主发布状态在 SQLite；直接 ReworkService 的保护只检查 RDS publish_record，不能完整识别主队列占用。

修复方向：统一 ReleaseGate；队列冻结清单并在实际上传前重验 hash；返工保护读取同一发布状态源。

### 7. 素材准入与内容质量尚未形成生产门槛

当前账户仍 testing。人物每人 1 张参考；穿搭存在鞋履缺项和语义兼容性缺口；两个商品图包都是 limited。程序可读和视觉可用是两回事。

`services/preflight.py:108` 人物检查读取账户默认人物，不是实际轮换人物；仅 active 账户会要求至少 3 张参考。需要把准入检查作用于本次选中的完整素材组合，并进入真实生成入口。

建议按任务能力分级：有限图包可以做穿搭/结构中景，但不可宣称细节证明；需要商品细节的模板必须有对应参考。配套单品缺实拍时保留 AI 派生来源，禁止当成真实商品凭证。

## 次级问题与 BGM

- 失败单图审核也会缓存；“重试审核”可能复用同一次失败，而非重新判图。需将服务超时续跑与复核误判拆成两个操作。
- `RenderReviewService.record` 对已 release 版本缺少完整终态幂等与撤销边界，后写审核可能使不同入口判断不一致。
- BGM 仍在发布阶段选择，主排班路径已包含选曲与提交，不需要移到图文渲染阶段。缺少平台实际音乐回读核对；“已选/已提交”不能等同“平台实际使用正确”。
- 历史助手审图应有明确 reviewer_type，不能伪装成真人审批；修复历史标记应保留审计，不静默覆盖。
