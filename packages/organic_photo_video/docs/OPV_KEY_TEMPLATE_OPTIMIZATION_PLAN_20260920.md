日期：2026-09-20。OPV代码依据为1385111及当前工作区；同期原创项链提交不属于本轮。
依据：本目录 OPV_ROW373_COLOR_TUTORIAL_REVIEW_20260920.md、OPV_KEY_TEMPLATE_REVIEW_20260920.md。

## 1. 背景与本轮范围

目前已有账号预算供稿、素材消费、商品／人物参考、旅行与固定背景生成、原生图文发布。教程文案已部分接通，但渲染仍以整图叠字为主；温度主题仍偏裤裙投票；自由围巾旅行有漏围巾的真实样片。

本轮按业务用途修复，不把所有模板改成教程：

| 用途 | 涉及主题 | 本轮处理 |
|---|---|---|
| 讲解 | 配色教程、旅行穿搭攻略 | 共用结构化逐页内容；按需要配色说明或方法说明 |
| 条件指南 | 旅行温度穿搭 | 在既有主题下增加按条件给建议的表达，复用讲解页 |
| 展示／选择 | 一衣多穿、旅行打卡、普通四选一、MX发型四选一 | 保留图数与叙事；轻改同质化文案、文字遮挡 |
| 类目保障 | VN围巾旅行／围巾四选一 | 无商品编码也必须生成包含围巾的内容 |

保持：现有账号表和任务表、不加必填列／运营JSON、不加逐篇人工审核、不换模型、不增加生图张数或多轮审美重试、不改变发布渠道／BGM／账号授权。

旧穿搭拆解和冷热切换保留专用流程。本轮不开放此前disabled入口，不重构人物包，不批量重跑历史任务。

## 2. 架构收口：分清四种职责

```text
本篇设置 > 账号有效默认 > 允许的自动推导
                 ↓
有效需求：市场/语言、类目、主题、商品、背景、风格、条件来源
                 ↓
素材消费：方法与语义依据 + 按用途选择参考图片
                 ↓
现有规划调用：每篇问题 + 穿搭 + 每页职责/画面证据/文案
                 ↓
冻结内容卡、源图引用、排版区域、最终本地语言文字
                 ↓
程序排版 → 中文回写 → 原发布链路
```

- 类目决定应该出现什么：围巾类目要求围巾出现。
- 商品决定什么需要保真：填编码才锁定具体商品与变体。
- 主题决定讲什么：配色方法、温度条件、同件多搭或选择展示。
- 视觉预设决定背景和账号调性，不独自承担教程信息结构。

继续复用 effective_brief、style_profile、content_plan、content_card、layout_snapshot；新增语义放在现有JSON快照内，不新增业务表。主题执行能力集中解析一次，避免在供稿、规划、渲染分别靠主题字符串猜测。

新任务冻结内部 execution/plan/layout 版本，参与缓存指纹。旧任务保持旧快照；代码升级不自动改写历史成片或重算其合同。

## 3. 修复一：无商品编码时也要保留围巾类目

### 问题与模块

269行 `recvvcD2x9br89`：VN围巾旅行、无商品编码，Look A没有围巾。当前 photo_style_reference_supply.py 的适配器主要由 product.category 决定，无商品回落女装；指定商品的 accessories 覆盖逻辑无法保障自由围巾生产。

涉及：photo_category_registry.py、feishu_workflow.py、photo_reference_vision.py、photo_content_planner.py、photo_style_reference_supply.py、既有类目配置与QA上下文。

### 实施

1. 从任务/配方已解析的category_key生成类目上下文，传入规划、供图和既有QA；不从“商品为空”推导为女装。
2. 无显式类目时保留旧调用兼容；显式scarf时不得静默回落womenswear。商品类别与任务类别矛盾在付费生成前处理。
3. 为围巾配置增加一项轻量自由生产约定，例如 `required_visible_items: [scarf]`。它和 required_product_roles 分工：前者保障类目存在，后者保障指定商品身份。
4. 自由围巾任务由规划选择围巾颜色、花纹和搭配方式，冻结到每个look的accessories。主题若承诺“同一条围巾”，全篇复用同一围巾设定；普通选择内容不强制同款。
5. 指定围巾商品时，原product reference继续拥有颜色、纹样、外形等权威，不能被自由描述覆盖。
6. 既有视觉QA调用增加“该页是否出现可辨认围巾”的观察项，不增加新的模型调用。围巾完全缺失可使用既有一次修复预算；绕法、流苏轻微差异维持原规则，不再加像素级一致性门槛。
7. 没有围巾事实的来源素材可以贡献背景／配色，但不能成为删掉围巾的理由。

### 验收

无编码scarf任务 → 规划四个look均有围巾 → 实际生图请求保留 → QA能识别完全缺失。指定商品路径保持原商品保真；TH女装与MX发型不新增围巾要求。未修好前不扩大“自由围巾旅行”自动供稿范围。

## 4. 修复二：教程结构必须成为真正的渲染输入

### 当前缺口

photo_reference_vision.py还从旧slide_texts回装narrative_plan；photo_content_planner.py中完整guide helper没有实际消费链；photo_package.py给renderer的主要输入仍是字符串。色卡和图文分区无法通过这条接口实现。

### 最小数据结构

在每个post/item现有narrative_plan上补齐必要字段，复用已有look描述，不存第二套可独立修改的衣服：

| 字段 | 职责 |
|---|---|
| version、kind、question_zh | 版本、讲解类型、本篇问题 |
| takeaways | 本篇实际采用的方法，不固定每篇相同三条 |
| pages[].source_role | 引用对应look_a/b/c/d |
| pages[].key_point、visual_basis | 本页建议以及画面应提供的证据 |
| pages[].text | 显式headline/body，可选kicker/cta，均为发布语言 |
| pages[].color_chips | 配色页可选：示意色、颜色名、对应单品角色 |
| reference_basis | 已采用的来源页／方法，原创无来源允许为空 |

每篇独立，不能只取posts[0]。四个源图角色不强制四套完全不同；允许复用商品、鞋子、背景、相似造型。首图直接用look_a，不另选封面。

### 执行接线

1. 在现有规划调用中一起生成方法、look与逐页文字；保留公共JSON schema、商品、人物、背景、语言合同。
2. 将visual_basis编译到实际生图请求：讲鞋口就能看到鞋口，讲内搭就能看到内搭；不能只写在摘要。
3. 最终文案修正后，页面text成为冻结文字源；slide_texts是兼容投影。渲染、中文回写和检查均派生自最终文字。
4. content_card/layout_snapshot携带页级text、色卡与布局引用；检查序列化、白名单和validator，防止字段写了又被丢掉。
5. 教程以四页原生构建；旧五页/删重复封面转换仅服务旧合同，不能让教程反复折叠或回退投票。
6. renderer对新版本读取结构，旧版本继续parse_page_spec。不要仅增加标点规则来模拟结构化文案。

### 素材参考关系

颜色搭配方法、证据页和允许用途继续写入effective_brief.reference_basis，终选实际采用页进入prompt；语义页与上传图片分开。产品图只承担商品保真；可迁移的参考分区、配色信息组织用于选择程序布局。

若参考是“人物＋侧栏色卡”，不照搬人物、商品色值或原文，但允许采用这种通用信息组织。没有教程参考时，采用默认教程布局即可，不要求运营再找图、不增加万能模板复刻引擎。

## 5. 修复三：只做两种信息布局，先交付真实样张

共同底层：一个主图区＋一个解释区，沿用当前画布尺寸与账号色调。由内容kind选择默认布局，无需运营新增选项。

### 5.1 配色页：人物主图＋配色说明侧栏

- 主图区约占可用宽度的七成，侧栏约三成；这是默认参数，按现有画布及泰文宽度适配。
- 主图等比放入其区域，保留人物、商品和鞋脚；不能先铺满图再把侧栏盖在人身上。
- 侧栏展示该页两三种关键颜色、对应单品和短解释，例如“棕色外套／奶白内搭／深靛蓝下装”。小面积点缀按需要加入，不强制每页三块。
- 色块由程序绘制，是本篇搭配示意，不伪装商品实测色值；不要照抄参考中与本商品无关的颜色。
- 封面用一句概括整篇的问题，可有简洁配色提示；内页解释方法。避免封面只问深色牛仔裤，后页却主要讲裙装。

### 5.2 旅行攻略／温度指南：主图＋独立解释区

- 主图区约占高度的七成到八成，底部承载短标题和一句解释，图片区与文字区不重叠。
- 场景图保持完整生活场景，解释区延续账号中性色；不强迫模型生成复杂文字留白，不用一整块黑底盖鞋靴。
- 局部裁切可选，仅在原图清晰、证据可见时使用。没有清晰细节就用完整图，不启动额外生图或抠图系统。
- 保留现有泰文字体与组合字符处理；优先缩短句子、合理断行，有限缩字，不能无限缩字号。

### 5.3 生产分工与预算

模型产干净人物／场景图，程序负责文字与色卡。“生图不画色卡”可以保留，前提是程序随后确实补上。图片里商品／颜色与文字明显矛盾时走已有有限修复；轻微色温差仅记录，不能为调色重新开启循环。

先复用373或374源图完成配色重排，371源图完成攻略重排。只有实际主图无法体现关键方法时才修那一页，不默认四张全部重生。

## 6. 修复四：温度主题要回答条件，避免继续裤裙投票

模块：config/travel_theme_templates.json、photo_theme.py、photo_reference_vision.py、photo_content_planner.py及既有主题解析。

现有TEMPERATURE内有“A/B/C/D仍比较风格轮廓配色”的规则，不能简单追加“每页讲温度”造成前后冲突。本轮在唯一规则生成处按内容表达分支：

- 既有明确“搭配灵感”需求：允许同温度条件下多套展示，每页一句该条件下的穿着理由。
- “实用指南”需求：使用讲解结构；默认主题没有显式表达时，温度指南采用实用指南。本篇明确的表达覆盖继续按既有优先级。
- 不改旧冻结任务，不修改独立冷热切换三态流程。

温度来源只使用实际输入或已明确的内容条件。地点/月分本身不等于实时天气，不采用“现在东京就是X度”的表达。只有旧执行profile缺省15_22c时，不自动把它当运营明确温度；没有条件则做不含数值的穿脱指南。

示例：本篇选择“早晚偏凉、室内偏暖的旅行穿脱”，四页可以是：

| 页 | 要回答什么 | 画面依据 |
|---|---|---|
| 封面 | 温差旅行，怎样穿得方便调整？ | 一套完整示例 |
| 2 | 外套脱下后穿什么 | 内搭真实露出或外套搭在臂上 |
| 3 | 出门增加哪一层 | 对应外层／领口覆盖清楚可见 |
| 4 | 如何安排腿部覆盖和鞋履 | 下装与脚踝关系可见，附一句总结 |

这是方法示例，不要求以后每篇照此顺序，也不要求每页不同温度。一次只围绕本篇条件，不混入怕冷／怕热等多个受众变量，不做温度矩阵和保暖性能保证。

## 7. 展示型模板：小改即可

### 一衣多穿

保留同商品四搭和现有图数。以本篇商品及搭配价值生成主问题，减少每篇都问“裤子还是裙子”。如果采用实用表达，页内短句写一处变化，例如换深色下装／改变腰线／配件呼应；灵感表达保持简洁标签。不声称系法、拆解或穿脱步骤已经实现。

### 旅行打卡／拍照／环境协调

继续人物＋场景展示。标题从地点与实际搭配出发，选择轴可以是颜色与环境、轮廓或用途，只有本篇确实比较裤裙时才用裤裙问题。参考素材的地点与环境按既有用途规则使用，不强制每页换热门地标。

### 四选一

保留四宫格、A/B/C/D与投票。图片容器和文字fit使用同一个真实区域，解决预留20%却允许文字使用34%画高的边界风险。此为尺寸一致性修复，不增加新模型或叙事。

### MX发型四选一

保留独立wig planner/supply/QA。相同人物和机位有利于比较；短标签置于不遮头顶、发际线和发尾的预留区，文字底框按实测墨迹计算。仅在明确MX模板下调整版面，不把TH教程规则灌进MX。未启用的前后对比、脸型匹配、场景发型保持原状态。

### 摘要与命名

保留现有视觉预设ID和下拉值，避免重命名破坏历史匹配；在现有内容摘要显示：主题、实际背景、实际布局、具体问题、页职责。教程摘要不再显示“选择ABCD”；“纯色搭配解析”旁注明其背景属性，是否解析由本篇布局决定。

## 9. 测试、样片和完成标准

### 必要回归

- 无商品scarf任务不回落女装；指定围巾商品保持原身份；普通TH/MX不受影响。
- 实际入口→规划响应→每篇内容卡→冻结请求→renderer，色卡／标题／解释字段没有被白名单丢弃。
- 数量为2时每篇独立问题和页文案，不能复制第一篇。
- 无参考教程仍可使用默认布局；商品参考与布局参考不混用。
- 语言修正后，图上文字、兼容slide_texts与中文回写一致。
- 新温度指南不携带冲突投票指令；无明确温度来源不编造数字。
- 实测文字bbox完全位于其区域；四宫格图片区不被文字侵入；泰文组合字符不拆开。
- 旧冻结请求指纹／页数可读，原四选一、MX发型、旧拆解与冷热切换关键回归通过。

模型／飞书可用假响应，但以上消费者必须走真实代码。不要用“guide helper返回正确”替代整条接线验证。当前针对六组模块的已知基线为142项通过、41子测试通过。

### 最少真实样片

1. **零生图费用重排：**373或374配色、371攻略，用已有源图验证两种信息布局；旧四宫格用fixture或既有源图验证区域。
2. **新增一篇温度指南：**明确本篇条件，原四图上限，核对穿法证据及中文。若现有源图足够先复用，不为测试强制付费。
3. **新增一篇无编码围巾旅行：**四页围巾均明确可见、描述与实际一致。指定围巾商品以已有回归／样片验证，出现新疑问再补生成。
4. 一衣多穿、打卡、MX小修先用已有图片和文案离线验证，不为每个模板都生一套。

### 完成标准

- 技术：生产链可执行、字段冻结完整、续跑不变、没有扩大调用预算。
- 内容：标题概括整篇，页内回答本篇问题，画面能证明建议。
- 视觉：颜色与单品对应，文字不遮证据，信息分区在实际成片存在。
- 操作：不新增人工配置／逐篇审核，原发布链路和账号定位继续使用。

样张对照属于开发交付验收，不变成日常生产人工关卡。交付报告必须列出记录ID、实际加载版本、最终图片、中文与已知限制；不能以“图片SHA不同”“4页生成成功”代替视觉验收。

## 10. 灰度与回滚

只对新版本、对应类目／主题生效。先用选定测试任务验证，不全账号切换；不清理历史成片，不自动重跑未完成旧任务。问题仅涉及文字布局时保留源图重排；主题内容无法可靠修复时暂停该任务，旧展示任务继续运行。

回滚关闭新版本教程接线或恢复前一配置，保留其冻结版本与产物以便诊断；不能静默把攻略降级为四选一。VN本地默认目录仍有trial/disabled，历史线上又有产物，启用前核对当前实际加载来源；本轮不擅自覆盖状态。

本轮不做：更多主题、全量模板复刻、复杂系法连续步骤、全库素材重分析、人物体系重构、全局质检加严、实时天气或新的发布调度系统。
