# 主发布通道安全加固（2026-09-03）

本轮只修改代码、运行临时库/模拟适配器测试；没有执行真实上传、发布、外部 API 或生产数据库迁移。

## 已实现

- V2 入队前统一 ReleaseGate：active/released/selected 指针一致，revision 已 released，冻结输入与选择哈希正确，重新派生 render 输入指纹，最新匹配终审通过且来自可信人工或独立模型。助手审图/伪 human 不能放行。
- 冻结发布 manifest，含 task/revision/render/review ID、选择/输入/视频哈希、文件路径及文案；标题、商品上下文读取验收快照。重试入队不能覆盖不同 release。
- 主排班器先持久化提交占位，再验证冻结清单和本地视频字节；随后通过最多 20 秒的只读子进程重查当前 RDS release。核验失败或超时不上传、不提交。
- ReworkService 可调用 `services.release_gate.assert_main_queue_rework_allowed` 查询同一个主发布 SQLite；只读连接，不初始化/迁移数据库。待排期、提交中、已排期、已发布及未解除异常状态均阻止返工。
- NeoBund commit 只提交一次。响应丢失/空任务 ID/服务异常后先只读对账；无法确认时保留 `提交中`，错误注明“提交结果不明”，不释放、不自动重发。
- SQLite 提交前原子持久化 `submission_context_json`，包含稳定脚本键、账号、真实 auth ID、通道、预约时间、标题、商品与 BGM 请求。扫描恢复只对账，查到唯一匹配后补挂本地状态。不同脚本同标题不再误匹配；多个匹配也阻止自动恢复。
- 重复素材同步保留提交中状态，避免覆盖回待排期。新库 DDL/旧库幂等列升级均兼容；由实际发布器下一次启动时执行，不是本轮已部署迁移。

## 仍需运营验收/边界

- 本地冻结清单与生产 RDS 的跨数据库操作不是分布式事务；提交前再次核验和发布占位阻止正常返工入口，不能宣称跨系统绝对原子性。
- 自动对账目前查平台前 50 条；查不到不等于没有提交成功，继续保持提交中并等待人工核对，绝不据此重发。提交占位后、实际调用前崩溃也可能需要人工解除。
- V1 历史内容保留兼容，V2 新格式丢失 manifest 则失败关闭。未把全部历史 V1 内容追认成 V2。
- BGM 仍在发布阶段选择；此次冻结的是已选择/提交的音乐，不是平台最终实际音乐的验收证明。
- 需在用户明确授权真实发布时验收一次：冻结版本通过终审 → 发布前核验 → 平台回执/音乐核对。测试通过不代表本轮已完成真实发布验收。
