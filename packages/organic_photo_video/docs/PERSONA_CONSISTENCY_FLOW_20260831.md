## 2. 单一数据权威

```text
飞书「原创人物模板库」
        │ 人工配置/审核；附件 token
        ▼
共享 persona_templates（SQLite）
        │ 同时保存稳定 local_path + Feishu file_token
        ├──────────────► 原创短视频流程
        └──────────────► OPV 图文视频流程
```

飞书是运营工作台；共享 SQLite 是运行时读取层。本地镜像不可省略，否则飞书 API 超额或临时下载链接失效时，模型拿不到人物参考图。

## 3. 原创短视频调用链

```text
产品 / 国家 / 类目 / 展示方式
        ▼
筛选兼容 Persona（可由穿搭模板给 preferred_persona_ids）
        ▼
任务级只选择一次
        ▼
冻结 persona_id + template_version + identity_lock
     + reference_assets + structured_snapshot_hash
        ▼
商品参考图 + Persona 参考图生成统一首帧
        ▼
后续视频只继承该首帧和冻结人物合同，不再重新选人
```

关键规则：商品参考图只控制商品；商品图中的模特、脸、妆发、滤镜和背景都不是人物权威。人物脸、肤色、发型只由 Persona 参考包和冻结身份合同控制。

## 4. OPV 图文视频调用链

```text
账号 allowed_persona_refs
        ▼
任务 planned_persona_ref（未指定则使用账号 persona_ref_id）
        ▼
计划时冻结 Persona 完整快照
        │ 同时冻结 persona_id + structured_snapshot_hash + 参考图 SHA256
        ▼
P1：商品参考图 + Persona 参考图
        ▼
P2-P5：商品参考图 + Persona 参考图 + P1 连续性锚点
        ▼
单图 QA：商品一致 + 人物一致 + 穿搭 + 场景 + 真实感
        ▼
五图组 QA：商品 / 人物 / 穿搭 / 场景跨图一致 + 镜头差异
        ▼
人工审核后才允许渲染 / 发布
```

同一任务不得逐张随机 Persona。需要比较人物 01/02/03 时，应建立三个任务，每个任务固定一个 `planned_persona_ref`，避免把“人物差异”和“模板/主题差异”混在同一组结果里。泰国 OPV 测试账号未显式指定时默认使用人物 01。

## 5. 参考包标准

每个 Persona 推荐 5 张，最低 3 张：

1. 正面胸像或半身，完整五官、自然表情；
2. 左或右 45° 半身，用于稳定侧脸；
3. 正面全身，用于稳定身形和比例；
4. 另一侧 45° 或自然回眸；
5. 自然生活动作图，用于验证动态姿态下不换脸。

参考包内必须保持相同脸型、五官、肤色区间、发色、基础发型和年龄感。服装、姿态与背景可以变化，但不要用强滤镜、浓妆、遮脸、大逆光或多人图。

## 6. 当前可达到的效果

- 目前每人只有 1 张正面图：可以用于小批测试，但在全身、侧脸、回眸和大动作画面中仍可能漂移，不能承诺稳定生产。
- 补齐 3–5 张同身份参考图后，再配合任务级冻结、P1 连续性锚点和人物视觉 QA，能够显著降低跨图换脸、肤色变暗和年龄漂移。
- 验收门槛：单图 `persona_fidelity >= 80`；五图组 `persona_consistency >= 80`；任一人物维度低于 70 直接判失败，不进入自动发布。
