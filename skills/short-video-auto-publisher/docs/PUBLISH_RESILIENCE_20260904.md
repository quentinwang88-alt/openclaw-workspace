## 故障边界

1. 创建前占位；不明确的网络结果进入待对账，不自动再次 POST。
2. NeoBund 返回的任务 ID 先持久保存，再更新排期状态；本地状态更新失败按已知 ID 修复。
3. 已有任务先保留；旧任务查询失败不阻挡无关的新任务创建。
4. 401 仅尝试一次刷新并验证；失败暂停该客户端本轮请求，不反复自动登录。
5. 凭证仅从精确匹配的 NeoBund 专用浏览器读取，不打印、不进入仓库；验证成功后更新本机私有配置。
6. 发布数据库是状态真源。飞书回写失败只延期投影，不回滚发布、不重新创建任务。
7. 每轮即使零新增任务，也补写与数据库不一致的飞书状态；已删除源记录跳过。
8. 明确未提交的恢复性错误按候选单独退避（首次等 1 小时，第二次等 2 小时，第三次停止）；认证失败不计为内容失败。

浏览器凭证恢复需要单独授权后，在本机配置启用
`neobund_browser_auth_refresh_enabled: true`。默认不因部署代码而自动读取浏览器凭证。

## 限定操作

正式补排前先核对远端已有任务的账号、remark/脚本 ID、计划时间与状态。

```sh
python3 run_pipeline.py schedule --publish-mode auto \
  --canonical-key '<准确内部脚本键>'
```

多个脚本重复传 `--canonical-key`。不要为了几条补排运行全量 `run-all`。
`sync-results` 和 `sync-bgm-status` 不创建发布任务。

## 验收重点

- 超过两小时的未来任务能够创建；不足半小时自动顺延。
- 同产品同家族的多个不同脚本可以排期。
- 重跑不重复提交；超时/本地回写故障后不会盲目重发。
- 401 刷新最多一次，凭证不暴露；历史查询错误逐条隔离。
- 飞书失败后下一轮可补写，未变化字段不重复写。
- BGM 实际 ID 和选中 ID 一致才显示“已确认一致”。

本次不引入自动重剪卡点，也不把“强节奏选曲”表述为已实现精准卡点。
