## 2. 统一行模型

目标 Base 使用五张用途数据表隔离阅读层级：

```text
文本                主字段/行标题
唯一键              幂等键
数据类型            机会卡/信号聚合/规格风险/原子证据
分析批次            VOC分析批次
市场/类目/产品形态  业务范围
报告链接            当前运行的飞书报告
内容指纹            判断是否需要更新
更新时间            ISO8601
```

数值字段：

```text
证据商品数
证据数
来源批次数
最大单商品贡献
```

其余字段使用文本类型，避免单选选项变化造成同步失败。

默认配置五张数据表：

```text
01_VOC机会看板 仅机会卡，沿用用户提供链接中的原数据表
02_规格与风险 仅规格风险，用于产品定义与避坑
03_信号分析   仅聚合信号，用于验证机会强弱
04_原始证据   仅原子证据，用于回溯消费者原话
99_后台全量   全部记录和字段，仅供维护
```

主表仅保留6条机会卡；另外三张业务表分别保存规格、信号和原始证据。后台全量表保留316条统一记录，确认其写入数量正确后才允许清理主表中的明细行。

## 3. 四类记录

### 机会卡

唯一键：`opportunity:{opportunity_id}`。

写入用户任务、未满足需求、机会假设、必备规格、可选升级、规避项、检查项、支持/风险信号、置信度和限制。

### 信号聚合

唯一键：`signal:{batch_id}:{signal_summary_id}`。同一分析批次重跑时保持稳定。

写入信号标签、产品形态、证据指标和置信度。`product_form=null` 显示为“跨形态”。

### 规格风险

唯一键：`spec:{item_id}`。

写入规格类型、规格/风险项、消费者原因、适用形态和置信度。

### 原子证据

唯一键：`atomic:{atomic_evidence_id}`。

写入原始VOC片段、证据来源商品ID、属性组、信号标签、正负向和原子证据ID。

## 4. 幂等和容错

- 先按 `唯一键` 查询已有行。
- `内容指纹` 未变化时跳过。
- 有变化时批量更新。
- 无对应键时优先填充整行为空的默认空白行。
- 剩余数据批量新增，每批最多100条。
- 不删除任何已有记录。
- 已存在同名字段时不修改类型。
- 先确保目标表字段完整，再创建报告；随后同步记录，确保所有行可写入报告链接。
