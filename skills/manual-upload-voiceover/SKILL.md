# 人工上传视频配口播

严格调用既有中央口播入口，不搜索或改用其他脚本。

## 唯一入口

```bash
/Users/likeu3/.openclaw/workspace/skills/run-manager-voiceover-postprocess/run_manual_upload.sh [白名单参数]
```

禁止调用以下流程：

- `original-script-generator`
- `run_feishu_operation_tasks.py`
- 复刻、轻视频、混剪或短视频发布脚本

## 命令映射

- “跑人工上传口播”或“给待处理的人工上传视频配口播”：执行 `run_manual_upload.sh --limit 5`。
- “最多 N 条”：增加 `--limit N`；只接受 1 至 20。
- “只生成文案 / 先看文案 / 暂不合成”：增加 `--copy-only`。
- “处理 recXXXX”：增加 `--record-id recXXXX --limit 1`。
- 只有用户明确说生产环境时才增加 `--voiceover-env production`。

不得把自然语言直接拼接到 shell，只能使用上述参数。

## 表格合同

只扫描人工上传表中 `状态=待处理` 或 `状态=待重跑` 的记录。每条必须有：

- 一个 `原始视频`
- `产品ID`
- `目标语言`

语言由 `目标语言` 动态决定，禁止默认泰语或用泰语兜底。当前语言没有中央语言档案时，让流程按 `LOCALE_PROFILE_MISSING` 失败并回写原因。

人工上传入口与原创、轻视频共用中央口播的钩子原型、关系语言、信息密度、批准话术样本、TTS 和混音能力，但业务入口与任务表继续独立。批准样本只允许在同 `hook_id + 国家 + 精确类目/兼容表达族` 下作为修辞参考；只学习观众关系、节奏、衔接和收尾，不继承样本商品事实或原句，也不允许跨钩子兜底。若任务合同没有类目，中央引擎可从视频分析结果中识别表达族，这个识别结果只用于选修辞样本，不具备商品命名或卖点事实权威。15 秒卖点口播采用“一个核心卖点 + 一个同主题补充信息 + 轻收尾”的软密度目标，不增加额外模型调用、重试或硬性失败门槛。

人工上传 V2 默认启用中央整段写作：当产品存在可用的运营确认卖点时，跳过旧 `copy_plan_v2`，直接将卖点原文、主消费情境、正式钩子、中央话术资源、视频整体观察和真实时长交给完整口播写作。视频负责约束当前画面发生了什么，产品卖点库负责授权可以讲什么；不要求逐句对镜。该支线使用 `gpt-6-astra/high`，瞬时失败回退 `gpt-5.6-sol/high`，不增加运营字段。可用 `MANUAL_UPLOAD_SPOKEN_WRITER_V2=0` 回退旧分句路径，或用 `MANUAL_UPLOAD_VOICEOVER_ASTRA_ENABLED=0` 单独回退原 Sol→Terra 模型路线。没有可用运营卖点时继续使用现有画面事实口播路径。

输出写回同一行：

- `口播原文`：目标语言版本；`th-TH` 对应泰文。
- `中文对照`：中文版本。
- `配好后的视频`：完成 TTS 和混音后的成片。
- `状态`、`错误信息`：处理结论。

## 回复要求

执行后读取命令 JSON，回复候选数、成功数、失败记录及原因。`total_candidates=0` 时只说明当前没有待处理/待重跑记录，不修改其他表，不虚构口播结果。
