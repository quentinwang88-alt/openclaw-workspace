# 商品级口播内容记忆 V1

## 目标

同一商品分多批生产 8–10 秒基础视频、18–24 秒增强视频和复刻视频时，允许商品事实重复，但避免连续复用相同钩子句、文案结构和卖点展开顺序。实现只扩展现有中央口播引擎，不修改智能混剪的镜头选择与视觉证据逻辑。

## 单一台账

中央口播库新增 `product_voiceover_content_ledger`。每个口播任务保存：

- 商品、来源系统、视频、内容格式和批次。
- 钩子原型、卖点 ID 及其顺序。
- 钩子中文句、目标语言全文、中文全文和标准化指纹。
- `reserved / committed / released` 状态。

旧的 `product_hook_claim_usage` 会在引擎初始化时幂等回填，不需要人工迁移历史任务。

`product_identity_aliases` 以外部商品编码作为稳定主身份，把 `OSG_...` 等内部 ID、运行管理表商品编码归到同一个商品。别名首次登记时会同步归并已经存在的台账记录，因此不会只对新任务生效。

长视频由 `content_production_batches` 自动分配 `<商品编码>_<日期>_B01` 形式的批次号。同一个 `plan_version` 重试时复用原批次，新计划才递增到 `B02`。短视频和复刻视频没有额外运营字段时，按飞书记录创建时间的 10 分钟窗口自动成批；若表中已有“批次ID”，则优先采用显式值。

## 三种格式规则

| 格式 | 生成约束 | 同格式全文相似度门槛 |
|---|---|---:|
| `basic_8_10` | 一个核心卖点 + 一个画面证明，避免压缩成长卖点清单 | 0.82；同批 0.78 |
| `enhanced_18_24` | 2–3 个卖点形成证据链，轮换证据顺序、过渡和结尾 | 0.76；同批 0.72 |
| `generated_long_voiceover` | 依据实际长成片建立紧凑证据链 | 0.78；同批 0.74 |
| `remake_voiceover` | 以复刻成片节奏和可见动作为先，不强套长视频结构 | 0.87；同批 0.83 |

跨格式不是简单判重：相似度达到 0.92 才拦截；完全相同的全文始终拦截。这样短视频可以复用长视频中的真实卖点，但不能直接截取同一段话反复使用。

## 执行时序

1. 先把入口商品 ID 归一成 canonical 商品编码，再写入 `content_format`、`batch_id` 和来源上下文。
2. 分配钩子和卖点时统计最近 50 条已提交记录及未过期占位。
3. 选中组合后占位 2 小时，避免紧邻任务继续把它当成未使用组合。
4. 模型生成前收到最近 8 条商品文案摘要和对应格式指令。
5. 正式文案在 TTS 前与最近 50 条全文比较；命中后在原有三次修订循环内重写。
6. 通过质检后提交台账；生成失败、三次修订仍失败或流程异常时释放占位。

长视频规划会在创建变体前读取同一台账：先降低近期高频钩子、卖点和配对的权重；同一策略池的所有唯一组合使用完之前不重复精确组合。重要钩子和核心事实没有硬次数上限。

## 运维查看

```bash
python3 scripts/run_pipeline.py --db var/light_tryon.sqlite3 narrative content-memory \
  --product-id <商品ID>
```

输出包含最近使用数量、钩子计数、卖点计数、配对计数及最近 12 条简要记录。它只读中央台账，不修改生产任务。
