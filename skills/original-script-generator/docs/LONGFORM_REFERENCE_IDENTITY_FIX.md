# 长视频人物与闭合结构输入修复

## 查到的问题

两条历史任务LFJ_2DAED4B5487C689808DB、LFJ_CFCED968B1A227A6980B均冻结单张旧人物图。当地共享库已配置多视角人物包，但原选择只考虑关联、用量和优先级；下载时也丢失主图/侧脸标记，最终按SHA排序。商品P1明确写“拉链与按扣”，共享闭合编译却只识别单排扣，因此状态UNAVAILABLE、负向要求又要求保留拉链。中央口播曾扫描整张身份锁，包括负向文字，可能将“禁止拉链”当成拉链存在。

## 修正边界

- 只由长视频请求标记启用图包软优先。明确穿搭关联仍最高优先；无兼容图包时单图正常回退。图包以已有不同视角role识别，不新增运营字段或生成参考图。人物缓存和冻结清单保留原主图/视角/人物ID；所有长视频生图入口按实际附件次序说明用途。
- 长视频入口复用原商品身份编译，补充独立mechanisms，不推断未知扣数或单/双排。人工纠错优先于模型观察，但须产品与完整商品图片SHA集合均匹配；不把某件按扣外套变成全局禁止拉链。原锚点/冻结方向包留审计，模型可见商品事实投影先撤回冲突结构，再交给主脚本、首帧、分段与中央口播。
- 纠错文件位于共享运行数据，不在代码内硬编码SKU，不写RDS/飞书。本次依据用户此前确认保存了这套蓝色图片版本的SNAP-only。变更图片集合后不命中，不能自动推断为相同SKU外观。
- 未重跑历史文本、媒体或更改运营关联；旧resume仍使用旧冻结结果。新任务/replan才生效。人物模板源数据仍由已有飞书刷新流程维护。
