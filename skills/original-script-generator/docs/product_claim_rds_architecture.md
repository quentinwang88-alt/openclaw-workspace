# 产品卖点 RDS 存储架构

## 结论

产品卖点域以 RDS 为唯一持久化权威。飞书是运营录入与确认界面，不是运行时数据库；
`voiceover.sqlite` 是归一化工作区、开发测试后端和可重建缓存，不参与生产双主。

## 权威表

| RDS 表 | 所有者 | 内容 | 更新方式 |
| --- | --- | --- | --- |
| `cc__claim_concepts` | 中央卖点域 | 标准概念、别名、主题、默认风险 | 配置种子幂等发布 |
| `cc__product_claim_sources` | 中央卖点域 | 飞书确认原文、来源、哈希、优先级 | 按来源哈希幂等写入 |
| `cc__product_claims` | 中央卖点域 | 标准化结果、审核状态、表达强度、风险 | 按 `claim_id` 幂等更新 |
| `cc__claim_video_evidence` | 中央卖点域 | 视频对卖点的支持、未知或冲突证据 | 按 `evidence_id` 幂等更新 |

四张表使用 `cc__` 命名空间，与原创脚本 `osg__*`、结构发现 `sd_*` 等业务库隔离。
跨库关系只保存稳定 ID，不在 RDS 中建立指向某条本地视频分析记录的强外键。

## 写入链路

```text
飞书人工确认
  -> 本地归一化工作区（可重建）
  -> 单事务 UPSERT 到 RDS cc__*
  -> 按主键逐表校验
  -> 成功后脚本规划从 RDS 读取并冻结批次快照
```

RDS 写入失败时，任务失败并保留本地工作结果供重试；不得继续用较旧 SQLite 数据生成。
迁移和日常同步都只新增或幂等更新，不删除历史行。

## 读取与隔离

- 原创、种草和长视频共享同一份 RDS 卖点事实与证据边界。
- 三条业务线分别投影为自己的内容角色、提示词和质检，不共享销售论证逻辑。
- 每个生成批次把使用到的卖点 ID、正文和快照哈希冻结进自己的任务库。
- 后续运营修改卖点只影响新批次，不反向改写历史脚本。
- 显式传入本地数据库路径时才使用 SQLite，供单元测试与离线诊断。

## 配置和迁移

- 连接优先级：`PRODUCT_CLAIMS_DATABASE_URL`，其次复用 `LIKEU_AI_DATABASE_URL`。
- 生产同步使用 `--storage-mode rds`，缺少连接或发布失败即停止。
- 全量预演：`python3 scripts/migrate_product_claims_to_rds.py`
- 全量执行：`python3 scripts/migrate_product_claims_to_rds.py --apply`
- 单品执行：追加 `--product-code <产品编码>`。

本地库在迁移成功后暂不删除。待所有消费者稳定读取 RDS 后，可把它降为按需重建的缓存，
但不应继续作为人工修改或生产读取入口。
